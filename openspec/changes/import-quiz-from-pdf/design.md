# Design

## Context

Изменение повторяет устройство `import-quiz-from-web-page`: скил в `.claude/skills/`, правила генерации в `tools/quiz-import/card-rules.md`, отправка через `tools/quiz-import/post_cards.py` (`check` и `post`). Новое по сравнению с ним — только получение текста из PDF, работа с большими документами и выбор страниц. Требования — в `specs/quiz-from-pdf/spec.md`.

## Goals / Non-Goals

**Goals:**
- Импорт по одной команде: `/quiz-from-pdf <путь> [страницы] [количество]`.
- Ноль новых зависимостей: ни Python-пакетов, ни системных утилит, которых нет на macOS по умолчанию.
- Максимальное переиспользование скрипта и правил импорта со страницы.

**Non-Goals:**
- Изменения в `post_cards.py`: его возможностей хватает.
- Скрипт извлечения текста (pypdf, pdftotext и т. п.).
- Кэширование прочитанных документов между вызовами.

## Decisions

### 1. Чтение PDF — встроенный инструмент Read
Read в Claude Code читает PDF вместе с текстом и изображениями страниц, поэтому отсканированные страницы распознаются без OCR-библиотек. Ограничение — не больше 20 страниц за вызов (параметр `pages`), поэтому документ читается частями.
- *Альтернатива — `pdftotext` или `pypdf`.* Это внешняя зависимость, которой нет на чистой macOS, к тому же без OCR для сканов.

### 2. Число страниц
Сначала `mdls -raw -name kMDItemNumberOfPages <файл>` (есть на macOS). Если он вернул `(null)`, например у неиндексированного файла, — `pdfinfo`, если утилита установлена. Если ни один способ не сработал, документ читается частями по 20 страниц, пока Read не сообщит, что страницы закончились. Тогда ограничение в 100 страниц срабатывает, как только прочитана сто первая страница: скил останавливается и просит указать диапазон.
- *Альтернатива — подсчёт `/Type /Page` регулярным выражением.* Ненадёжно для PDF со сжатыми потоками объектов.

### 3. Распределение карточек по документу
Выбранный диапазон делится на части по 20 страниц. Каждой части выделяется квота карточек, пропорциональная числу её страниц: `ceil(N × страниц_в_части / всего_страниц)`. Скил читает часть, генерирует для неё кандидатов по `card-rules.md`, затем объединяет кандидатов и урезает их до N, оставляя карточки из разных частей. Так выполняется требование о распределении, и в контексте не приходится держать все 100 страниц сразу.
- *Альтернатива — прочитать весь диапазон и сгенерировать за один раз.* Проще, но модель склонна строить вопросы по началу документа, а контекст переполняется на больших диапазонах.

### 4. Фильтрация служебного текста
В SKILL.md добавляется PDF-специфичное правило поверх `card-rules.md`: игнорировать колонтитулы, номера страниц, оглавление, список литературы и подписи без содержательного текста. Общий файл правил не меняется, чтобы не затронуть скил импорта со страницы.

### 5. Отправка
Без изменений: `post_cards.py check` перед чтением документа, затем JSON во временной директории и `post_cards.py post`. В `allowed-tools`: `Read`, `Write`, `Bash(python3 tools/quiz-import/post_cards.py:*)`, `Bash(mdls:*)`, `Bash(pdfinfo:*)`.

### 6. Тестирование
Дубликаты, частичные ошибки и отчёт уже покрыты автотестами `post_cards.py`. Для поведения скила используются тестовые PDF в `tools/quiz-import/fixtures/`:
- `short.pdf` (2–3 страницы текста),
- `sections.pdf` (около 40 страниц с явными разделами),
- `scanned.pdf` (страницы-изображения),
- `blank.pdf` (пустые страницы),
- `protected.pdf` (с паролем).

Большой документ (более 100 страниц) не коммитится: он генерируется при проверке. Сценарии проверяются вручную на запущенном приложении.

## Risks / Trade-offs

- [Отсканированные страницы плохого качества распознаются с ошибками] → правило «ответ следует из текста» плюс отчёт со списком вопросов. Пользователь видит результат в UI.
- [Чтение 100 страниц расходует много токенов] → лимит в 100 страниц без явного диапазона и чтение частями. Пользователь может сузить диапазон.
- [`mdls` недоступен вне macOS] → предусмотрены запасные варианты: `pdfinfo`, затем последовательное чтение.
- [Квоты частей округляются вверх, и кандидатов получается больше N] → итоговое урезание до N предусмотрено в решении 3.
- [Тестовые PDF увеличивают репозиторий] → небольшие фикстуры (до 1 МБ в сумме). Большой документ генерируется, а не хранится.
