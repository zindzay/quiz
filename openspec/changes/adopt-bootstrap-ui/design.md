# Design

## Context

Интерфейс — `src/main/resources/static/` (`index.html`, `app.js`, `styles.css`), его раздаёт Spring Boot 4.1. Тёмная тема сейчас реализована через `@media (prefers-color-scheme: dark)` и CSS-переменные. Внешний вид зафиксирован 7 эталонными скриншотами (`ui-tests/`). PostToolUse-хук проверяет их после каждой правки в `static/`. Поведенческие e2e-тесты появятся в изменении `add-ui-e2e-tests`. Требования — `openspec/specs/cards-web-ui/spec.md` и delta этого изменения.

## Goals / Non-Goals

**Goals:**
- Bootstrap 5 как основа вёрстки, подключённый без npm, сборки фронтенда и CDN.
- Поведение страницы не меняется: сценарии `cards-web-ui` проходят без изменений в тестах.
- Тёмная тема по системной настройке сохраняется.
- Минимум собственного CSS: только то, чего нет в Bootstrap.

**Non-Goals:**
- JS-бандл Bootstrap (`bootstrap.bundle.min.js`): нынешняя страница не использует ни одного компонента, которому нужен JavaScript.
- Sass-кастомизация и своя палитра: используются стандартные цвета Bootstrap.
- Переключатель темы в интерфейсе.

## Decisions

### 1. WebJars и пути без версии
Зависимости `implementation("org.webjars:bootstrap:5.3.8")` и `implementation("org.webjars:webjars-locator-lite")`. Версией локатора управляет BOM Spring Boot (1.1.4). Если локатор есть в classpath, Spring Boot сам разрешает пути без версии: страница ссылается на `/webjars/bootstrap/css/bootstrap.min.css`, и при обновлении Bootstrap менять HTML не придётся.
- *Альтернатива — CDN (jsDelivr).* Ноль зависимостей, но страница перестаёт работать без интернета и обращается к стороннему домену. Это противоречит новому требованию «Работа без внешних ресурсов».
- *Альтернатива — скопировать `bootstrap.min.css` в `static/`.* Работает, но обновление становится ручным, а версия не видна в `build.gradle.kts`.
- *Альтернатива — `org.webjars.npm:bootstrap`.* Содержимое то же, но классический WebJar — стандартный путь, который описан в документации Spring Boot.

### 2. Тема через `data-bs-theme` и небольшой скрипт
Bootstrap 5.3 переключает тему атрибутом `data-bs-theme` на `<html>` и сам системную настройку не отслеживает. Новый файл `static/theme.js` подключается синхронно в `<head>` до стилей. Он ставит `data-bs-theme` по `matchMedia('(prefers-color-scheme: dark)')` и подписывается на изменение настройки. Синхронная загрузка в `<head>` нужна, чтобы при открытии не мелькала светлая тема.
- *Альтернатива — инлайн-скрипт в `<head>`.* Тот же эффект, но инлайн-скрипты мешают будущей политике безопасности контента (CSP).
- *Альтернатива — свои `@media`-правила поверх Bootstrap.* Пришлось бы вручную дублировать тёмную палитру для каждого компонента.

### 3. Соответствие разметки
| Элемент | Было | Станет |
|---|---|---|
| Контейнер | `main` с `max-width: 720px` | `main.container.quiz-main.py-4` (ширина — в `styles.css`) |
| Форма | `form` с собственной рамкой | `form.card.card-body.mb-4` с `.vstack.gap-3` |
| Поля | `textarea` | `.form-label` и `textarea.form-control` |
| Кнопка | `button` | `button.btn.btn-primary.align-self-start` |
| Ошибка формы | `p.error` | `div.alert.alert-danger.mb-0` с `role="alert"` |
| Статус списка | `p.status` | `p.text-body-secondary` |
| Список | `ul.cards` | `ul.list-unstyled.vstack.gap-3` |
| Карточка | `li.card` (свой класс) | `li.card.quiz-card` > `div.card-body` |
| Вопрос / ответ | `.question` / `.answer` | `p.quiz-question.fw-semibold` / `p.quiz-answer` |
| Раскрытие ответа | класс `revealed` на `li` | класс `revealed` на `li`, видимость задаёт `styles.css` |

Собственные классы получают префикс `quiz-`, чтобы не пересекаться с классами Bootstrap. В текущей вёрстке `.card` — свой класс, и он столкнулся бы с компонентом Bootstrap.

Атрибуты доступности (`role="button"`, `tabindex`, `aria-expanded`, `<label>` у полей, `role="alert"`) сохраняются: на них опираются e2e-тесты и пользователи с клавиатурой.

### 4. Что остаётся в `styles.css`
Ширина контейнера, `white-space: pre-wrap` и `overflow-wrap: anywhere` для текста карточек, `cursor: pointer` и `:focus-visible` для карточки, пунктирный разделитель над ответом и скрытие и показ ответа. Цвета берутся из переменных Bootstrap (`--bs-border-color`, `--bs-primary`), поэтому тёмная тема работает без отдельных правил. Ожидаемый объём — около 30 строк.

### 5. Тесты
- **Скриншоты.** Все 7 эталонов изменятся. Процедура такая:
  1. перевёрстка;
  2. `./gradlew screenshotTest` падает;
  3. показать вам список изменившихся скриншотов с путями к `*-diff.png` и `*-actual.png`;
  4. после вашего подтверждения выполнить `./gradlew screenshotUpdate`;
  5. просмотреть новые эталоны.

  PostToolUse-хук во время перевёрстки будет сообщать о расхождениях — это ожидаемо, эталоны до шага 4 не обновляются.
- **Поведение.** Существующие e2e-тесты из `add-ui-e2e-tests` должны пройти без изменений — это главная проверка, что перевёрстка ничего не сломала.
- **Новые требования.** В e2e-набор добавляются тесты:
  - тема: при `colorScheme: 'dark'` у `<html>` атрибут `data-bs-theme="dark"`, а фон `body` тёмный; при `light` — наоборот;
  - внешние ресурсы: все запросы страницы (`page.on('request')`) идут на хост приложения.

  Сценарий «Работа без доступа в интернет» покрывается тестом на внешние ресурсы: если сторонних запросов нет, отсутствие интернета на странице не сказывается.

### 6. Порядок относительно `add-ui-e2e-tests`
Это изменение реализуется после `add-ui-e2e-tests`. Тогда поведение страницы защищено автотестами до начала перевёрстки, а новые тесты из решения 5 ложатся в готовую e2e-инфраструктуру.

## Risks / Trade-offs

- [Страница станет «бутстраповской» на вид] → это осознанный выбор ради готовых компонентов. Палитру можно настроить через CSS-переменные Bootstrap отдельным изменением.
- [Размер CSS вырастет с ~3 КБ до ~230 КБ] → файл отдаётся локально и кэшируется браузером. Для локального приложения это несущественно.
- [Spring Boot 4 не разрешит путь без версии] → это проверяется первой задачей. Запасной вариант — путь с версией `/webjars/bootstrap/5.3.8/...` и отметка в `CLAUDE.md`, что при обновлении его нужно менять.
- [Reboot Bootstrap меняет базовые стили (шрифты, отступы, `textarea`)] → именно это и покажут скриншоты. Решение по внешнему виду принимаете вы на шаге просмотра diff.
- [Хук на каждой правке во время перевёрстки возвращает ошибки скриншотов] → это ожидаемое состояние: правило из `CLAUDE.md` «эталоны только после подтверждения» соблюдается, а ошибки — сигнал, а не повод чинить эталоны.

## Migration Plan

Данные и API не затрагиваются. Откат — вернуть `static/`, зависимости и эталоны из git.
