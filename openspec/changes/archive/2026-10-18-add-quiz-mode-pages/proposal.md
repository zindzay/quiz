# Proposal

## Why

Сейчас приложение — одна страница, где форма добавления и список карточек с ответами по клику. Для самопроверки это неудобно: весь набор вопросов виден сразу, порядок всегда одинаковый, и непонятно, сколько ответов на самом деле знаешь. Нужен режим теста: случайный набор из заданного числа вопросов, по одному на экране, с итогом в конце. Вопросы, на которые пользователь не знал ответа, должны возвращаться в следующие тесты, пока он их не выучит. Добавление и просмотр всех карточек при этом становятся отдельными задачами и получают свои страницы.

## What Changes

- **Три страницы вместо одной**, с навигацией «Тест · Добавить · Все карточки» в шапке каждой:
  - `/` — **тест** (новая главная);
  - `/add.html` — **добавление**: только форма; после успешного добавления — сообщение «Карточка добавлена», поля очищаются;
  - `/cards.html` — **все карточки**: список с раскрытием ответа по нажатию, как сейчас на главной.
- **Тест:**
  - пользователь задаёт количество вопросов (по умолчанию 10) и начинает тест;
  - приложение выбирает это число **случайных карточек без повторов** из хранилища; если карточек меньше — берёт все и сообщает об этом;
  - карточки показываются **по одной**, карточка **квадратная**, с номером «Вопрос 3 из 10»;
  - нажатие на карточку **показывает правильный ответ**; после этого — кнопки «Знал» и «Не знал», которые засчитывают ответ и переходят к следующей карточке; вернуться к прошлым или пропустить вопрос нельзя;
  - после последней карточки — **итог** «Знал 7 из 10» и кнопка «Новый тест»; итог не сохраняется, обновление страницы начинает тест заново.
- **Повторение вопросов «Не знал»:**
  - «Не знал» ставит карточку **на повторение**, «Знал» снимает с него; отметка сохраняется на сервере сразу при ответе;
  - в следующем тесте на N вопросов карточки на повторении занимают места **в первую очередь**, остальные места — случайные карточки; если на повторении больше N — берутся N из них;
  - карточка на повторении помечена на экране теста надписью «На повторении».
- **API:**
  - у карточки появляется поле `review` (логическое, по умолчанию `false`);
  - `PUT /api/cards/{id}/review` с телом `{"review": true|false}` — поставить или снять с повторения;
  - `GET /api/cards/random?count=N` — до N случайных карточек без повторов, сначала карточки на повторении; `count` от 1 до 100, иначе 400.
- **Формат CSV:** новая колонка `review` (заголовок `id,question,answer,review`). Файл прежнего формата читается как есть (все карточки не на повторении) и переводится в новый формат при первой записи — ручная миграция не нужна.
- **BREAKING (интерфейс):** по адресу `/` больше нет формы и списка — они переехали на `/add.html` и `/cards.html`. Данные и существующие методы API не меняются.

Вне рамок этого изменения:
- сохранение итогов тестов и статистика по карточкам (сохраняется только отметка повторения);
- выбор вопросов по теме или колоде;
- ввод ответа текстом и автоматическая проверка;
- редактирование и удаление карточек.

## Capabilities

### New Capabilities

- `quiz-session`: прохождение теста в браузере — выбор количества, показ случайных карточек по одной, раскрытие ответа, самооценка и итог.

### Modified Capabilities

- `cards`:
  - меняются «Структура карточки» (поле `review`) и «Некорректный файл данных» (допустимы два заголовка);
  - добавляются «Файл данных прежнего формата», «Отметка повторения» (`PUT /api/cards/{id}/review`) и «Случайная выборка карточек» (`GET /api/cards/random`).
- `cards-web-ui`:
  - «Главная страница» переименовывается в «Страница всех карточек» и переезжает на `/cards.html`;
  - «Форма добавления карточки» переезжает на `/add.html`: вместо появления карточки в списке — сообщение об успехе;
  - «Тема оформления» и «Работа без внешних ресурсов» распространяются на все страницы;
  - добавляется требование «Навигация между страницами».

## Impact

- `src/main/java/org/valgor/quiz/`:
  - `model/Card` — поле `review`;
  - `repository/CardRepository`, `CsvCardRepository` — колонка `review`, чтение прежнего формата, обновление карточки;
  - `service/CardService` — отметка повторения и случайная выборка с приоритетом повторения;
  - `web/CardController` — `PUT /api/cards/{id}/review` и `GET /api/cards/random`;
  - тесты `CsvCardRepositoryTest`, `CardServiceTest`, `CardApiTest`, `RestartPersistenceTest`.
- `data/cards.example.csv` — новый заголовок. Пользовательский `data/cards.csv` переводится в новый формат автоматически при первой записи.
- `src/main/resources/static/`:
  - `index.html` и `app.js` превращаются в страницу теста;
  - новые `add.html`, `add.js`, `cards.html`, `cards.js`;
  - общий фрагмент навигации и стили квадратной карточки в `styles.css`.
- `ui-tests/`:
  - e2e-тесты переезжают на новые адреса, появляются тесты теста;
  - скриншотные тесты и эталоны для трёх страниц — **эталоны меняются**, обновляются только после того, как пользователь просмотрит разницу.
- `README.md`, `CLAUDE.md` — описание страниц и нового метода API.
- Новых зависимостей нет.
