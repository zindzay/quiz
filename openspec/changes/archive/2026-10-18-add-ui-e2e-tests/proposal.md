# Proposal

## Why

Шесть сценариев спецификации `cards-web-ui` сейчас проверяются вручную в браузере (так закрывались задачи 5.2–5.3 изменения `add-card-view-and-create`). Ручную проверку легко пропустить при следующих правках, а скриншотные тесты (`add-ui-screenshot-tests`) фиксируют только внешний вид, а не поведение. Нужны автоматические браузерные тесты, которые проверяют каждый сценарий на настоящем приложении и запускаются в сборке.

## What Changes

- Поведенческие e2e-тесты на Playwright Test в `ui-tests/`, по одному или несколько на каждый сценарий `cards-web-ui`, плюс требование «сервер недоступен». У этого требования нет отдельного сценария, но оно описано в «Ошибки при добавлении».
- Тесты работают с настоящим API: каждый тест поднимает собственный экземпляр приложения с пустым временным файлом данных. Так тесты изолированы друг от друга и от данных пользователя.
- Задача `./gradlew e2eTest` входит в `check` и `build`. Хук Claude Code из `add-ui-screenshot-tests` дополнительно запускает e2e-тесты.
- В `CLAUDE.md` убирается упоминание ручной проверки UI: сценарии `cards-web-ui` проверяются автотестами, и новые сценарии UI тоже должны сопровождаться e2e-тестом.

Вне рамок этого изменения:
- новые сценарии и изменения поведения UI;
- браузеры, кроме Chromium;
- CI.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Требования `cards-web-ui` не меняются, меняется только способ их проверки, поэтому для изменения установлен `skip_specs: true`.

## Impact

- `ui-tests/`: отдельный конфиг `playwright.e2e.config.ts`, фикстура запуска приложения, тесты в `ui-tests/e2e/`.
- `build.gradle.kts`: задача `e2eTest`, зависимость `check` → `e2eTest`.
- `.claude/hooks/screenshot-check.sh`: запускает `screenshotTest` и `e2eTest`; скрипт переименовывается в `ui-check.sh`.
- `CLAUDE.md`: раздел о тестировании UI.
- Зависит от `add-ui-screenshot-tests`: нужны `ui-tests/`, Node-плагин, `playwrightInstall` и хук.
- `./gradlew build` станет дольше примерно на 20–40 с из-за запуска приложения на каждый тест. Если не менялись ни интерфейс, ни jar, задача пропускается как UP-TO-DATE.
