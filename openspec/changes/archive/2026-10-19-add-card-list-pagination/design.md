# Design

## Context

`cards.js` загружает все карточки одним запросом `GET /api/cards` и выводит каждую в `<ul id="cards">` из шаблона `#card-template`. При удалении элемент списка убирается из DOM, массив карточек нигде не хранится. В e2e-тестах карточки — это `getByRole('list').getByRole('listitem')`. Навигация в шапке поэтому сделана не списком (`nav` со ссылками), чтобы `getByRole('list')` находил только карточки. Мотивация — в `proposal.md`, требования — в delta-спеке `cards-web-ui`.

## Goals / Non-Goals

**Goals:**
- Номера и страницы без изменений API, CSV и Java-кода.
- Не ломать селекторы существующих e2e-тестов списка.

**Non-Goals:**
- Серверная пагинация (`GET /api/cards?page=…`).
- Перенос фокуса и анимации при смене страницы.

## Decisions

**1. Пагинация на клиенте.** Страница по-прежнему загружает все карточки одним запросом, хранит массив в `cards.js` и рисует срез из 10 карточек. Карточки и так держатся в памяти сервера, а ответ на сотни коротких карточек — десятки килобайт. Альтернатива — `GET /api/cards?page=N&size=10`. Она меняет API и спецификацию `cards`, требует Java-кода и тестов. Кроме того, после удаления пришлось бы заново запрашивать страницу, чтобы подтянуть карточку со следующей. Выигрыш появится только на тысячах карточек, это вне рамок.

**2. Номер — позиция в массиве.** Номер карточки — `индекс + 1` в массиве `GET /api/cards`, который упорядочен по времени добавления (требование «Просмотр списка карточек» спеки `cards`). Номер выводится видимым текстом в начале области раскрытия (`.quiz-toggle`) перед вопросом: «11.». Он входит в доступное имя кнопки раскрытия, поэтому `getByRole('button', { name: /вопрос/ })` продолжает работать. Список остаётся `<ul>`, а не `<ol start>`: маркеры `<ol>` скрыты `list-unstyled`, их нельзя проверить по тексту, и скринридер прочёл бы номер дважды.

**3. Панель страниц — `nav`, не список.** Bootstrap предлагает `ul.pagination`, но второй список на странице сломал бы `getByRole('list').getByRole('listitem')`. Это та же причина, по которой навигация в шапке сделана не списком. Поэтому используется `<nav aria-label="Страницы списка">` с классами Bootstrap `pagination` / `page-item` / `page-link` на `div` и `a`. Классы Bootstrap от тега не зависят. Элементы панели:
- номера страниц и «Назад» / «Вперёд» — ссылки `<a href="?page=N">`;
- текущая страница — `aria-current="page"` и класс `active`;
- недоступные «Назад» и «Вперёд» — `page-item disabled` и `aria-disabled="true"` без `href`;
- «…» — `<span class="page-link">`, не ссылка.

**4. Смена страницы без перезагрузки.** Нажатие на ссылку панели перехватывается: `history.pushState` записывает `?page=N`, затем срез перерисовывается. На `popstate` (кнопки браузера) страница читает `page` из адреса и перерисовывает срез, повторного запроса к API нет. Ссылки остаются настоящими `href`, поэтому открытие в новой вкладке тоже работает. Номер вне диапазона приводится к ближайшей странице (`1…последняя`), нечисловой — к 1. Исправленный номер записывается `history.replaceState`, без новой записи в истории. Альтернатива — обычные ссылки с перезагрузкой страницы — проще, но каждый переход заново грузит все карточки.

**5. Удаление.** После успешного `DELETE` карточка убирается из массива, текущая страница перерисовывается целиком: номера сдвигаются, со следующей страницы подтягивается карточка. Если текущая страница стала пустой, номер уменьшается на один, и адрес обновляется через `replaceState`. Сообщение «Карточек пока нет» показывается, как и раньше, когда массив пуст. Ошибка удаления по-прежнему показывается на самой карточке, без перерисовки.

**6. Сокращённая панель.** При 7 страницах и меньше видны все номера. При большем числе видны 1, последняя, текущая и соседние с ней (±1), между несмежными номерами — «…». Набор номеров считает отдельная чистая функция `pageItems(current, total)`, её граничные случаи покрыты e2e-сценарием «Много страниц».

**7. Тесты.**
- E2E на каждый сценарий delta-спеки. Карточки создаются через `app.createCard()`: 25 карточек на сценарий за несколько секунд. Номера проверяются по тексту элементов списка, панель — через `getByRole('navigation', { name: 'Страницы списка' })`.
- Скриншоты: в `fixtures.ts` — генератор 25 карточек, новые снимки «список: страницы» (страница 2) в светлой, тёмной (`@dark`) и мобильной (`@mobile`) теме.
- Эталоны `list*.png` изменятся из-за номеров. Их обновление (`screenshotUpdate`) — только после того, как пользователь посмотрит `*-diff.png`.

## Risks / Trade-offs

- [Тысячи карточек — один большой ответ API] → Пока не проблема (ответ в десятки–сотни КБ). При необходимости — отдельное изменение с серверной пагинацией.
- [Номер не постоянный: после удаления у карточки другой номер] → Принятое решение (позиция в списке). В спеке это явно: «номера пересчитываются».
- [Две вкладки: карточку удалили в другой вкладке] → Список в этой вкладке устареет до перезагрузки, как и сейчас. Повторное удаление вернёт 404, а страница уже трактует 404 как успех.
- [Хук `ui-check.sh` прогоняет скриншоты после каждой правки `static/`] → Пока эталоны не обновлены, хук будет сообщать о расхождении `list*.png`. Это ожидаемо: эталоны обновляются по правилу из `CLAUDE.md` в задаче про скриншоты.
