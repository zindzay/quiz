# Design

## Context

Скил — это Markdown-инструкция для Claude Code (`.claude/skills/<name>/SKILL.md`), а не код приложения. Карточки генерирует сама модель, а детерминированную часть — проверку API, дубликаты и отправку — лучше вынести в скрипт, чтобы она не зависела от формулировок промпта. Приложение предоставляет `GET /api/cards` и `POST /api/cards` (изменение `add-card-view-and-create`). Требования — в `specs/quiz-from-web-page/spec.md`.

## Goals / Non-Goals

**Goals:**
- Импорт по одной команде: `/quiz-from-web-page <url> [количество]`.
- Детерминированная часть (проверка API, дубликаты, отправка, отчёт) покрыта автотестами.
- Скрипт отправки подходит для повторного использования в скиле импорта из PDF.

**Non-Goals:**
- Генерация карточек на стороне Java-приложения или через Anthropic API из бэкенда.
- Пакетный эндпоинт `POST /api/cards/batch`: при количестве до 50 карточек отдельных запросов достаточно.
- Обход нескольких страниц или всего сайта.

## Decisions

### 1. Загрузка страницы — инструмент WebFetch
WebFetch уже есть в Claude Code: он сам загружает страницу и превращает HTML в Markdown. Скил просит его вернуть основной текст как есть, без пересказа.
- *Альтернатива — `curl` и разбор HTML.* В текст попали бы навигация и скрипты, а очистку пришлось бы писать отдельно.
- Ограничение: страницы, которые рендерятся только через JavaScript, загрузятся пустыми. По спецификации это случай «недостаточно содержимого».

### 2. Генерацию выполняет модель по общим правилам
Правила лежат в `tools/quiz-import/card-rules.md`, и SKILL.md велит прочитать этот файл перед генерацией. Тот же файл будет читать скил импорта из PDF, поэтому правила не дублируются. Правила: один факт на карточку, ответ следует из текста, язык страницы, ответы короткие (1–3 предложения), без вопросов «да/нет» и без вопросов о самой странице («О чём эта статья?»). Модель записывает результат в JSON-файл `[{"question": ..., "answer": ...}]` во временной директории (scratchpad сессии).

### 3. Отправка — скрипт `tools/quiz-import/post_cards.py`
Python 3, только стандартная библиотека (`urllib`, `json`, `argparse`): на macOS python3 уже установлен, зависимостей ставить не нужно.
- `post_cards.py check [--api URL]` — `GET /api/cards`; код выхода 0, если API доступно, иначе 2 и сообщение с подсказкой `./gradlew bootRun`.
- `post_cards.py post FILE [--api URL]` — читает JSON, проверяет длину полей, загружает существующие карточки, отбрасывает дубликаты (сравнение `strip().casefold()`), отправляет оставшиеся по одной и печатает JSON-отчёт `{"added": [...], "skipped": [...], "failed": [{"question", "error"}]}`.
- Базовый адрес: `--api` > `QUIZ_API_URL` > `http://localhost:8080`.
- *Альтернатива — `curl` из промпта для каждой карточки.* Пришлось бы экранировать JSON в shell, дубликаты проверяла бы модель, и результат был бы невоспроизводим.
- *Альтернатива — скрипт на Java внутри Gradle-проекта.* Медленный старт и смешение инструментов с кодом приложения.

### 4. Расположение
Скрипт лежит в `tools/quiz-import/`, а не внутри папки скила, потому что его будут использовать два скила. В `SKILL.md` указан путь от корня репозитория. В `allowed-tools` скила разрешены `WebFetch`, `Write` и `Bash(python3 tools/quiz-import/post_cards.py:*)`.

### 5. Тестирование
- Скрипт: `unittest` с локальным `http.server` в отдельном потоке, который имитирует API. Тесты: `check` при доступном и недоступном API, дубликаты (регистр и пробелы, повторы внутри файла), частичная ошибка 400, слишком длинные поля, отчёт. Запуск: `python3 -m unittest discover tools/quiz-import`.
- Скил: ручной прогон по сценариям спецификации на запущенном приложении (статья, русская страница, 404, короткая страница, повторный импорт той же страницы).

## Risks / Trade-offs

- [Модель может сгенерировать неточный ответ] → в правилах сказано, что ответ должен следовать из текста; итоговый отчёт показывает вопросы, и пользователь может проверить их в UI. Ревью перед отправкой — отдельное изменение.
- [WebFetch может сократить очень длинную страницу] → скил предупреждает, что карточки построены по доступной части. Постраничную обработку длинных документов можно добавить позже.
- [Дубликаты по смыслу с другой формулировкой не отлавливаются] → допустимо: проверка по точному совпадению вопроса предсказуема и тестируема.
- [Приложение остановили между `check` и `post`] → `post` считает каждую сетевую ошибку неудачей, и отчёт это показывает.
