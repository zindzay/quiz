# Spec Delta

## MODIFIED Requirements

### Requirement: Вызов скила
Скил SHALL принимать обязательный URL страницы (http или https) и необязательное количество карточек от 1 до 50. Если количество не указано, скил SHALL работать в автоматическом режиме и сам определять число карточек (см. «Автоматический выбор количества карточек»). При отсутствии или неверном URL, а также при количестве вне диапазона скил MUST сообщить об ошибке до каких-либо сетевых запросов.

#### Scenario: Вызов с URL
- **WHEN** пользователь вызывает скил с URL `https://example.com/article` без количества
- **THEN** скил работает в автоматическом режиме и сам определяет число карточек по содержанию страницы

#### Scenario: Вызов с количеством
- **WHEN** пользователь вызывает скил с URL и количеством 5
- **THEN** скил генерирует не больше 5 карточек

#### Scenario: Неверные аргументы
- **WHEN** пользователь передаёт `ftp://example.com` или количество 100
- **THEN** скил сообщает об ошибке и не загружает страницу

## ADDED Requirements

### Requirement: Автоматический выбор количества карточек
В автоматическом режиме скил MUST выделить все ключевые положения основного текста страницы (определения, факты, числа, причины и следствия, шаги процессов, сравнения) и создать по одной карточке на каждое положение. Число карточек SHALL быть равно числу ключевых положений и MUST NOT ограничиваться 50. Каждый крупный раздел с осмысленным содержанием MUST дать хотя бы одну карточку.

#### Scenario: Короткая страница
- **WHEN** на странице без указания количества изложены три независимых факта
- **THEN** скил создаёт три карточки, по одной на факт, и не добавляет вопросов сверх содержания

#### Scenario: Длинная статья
- **WHEN** пользователь без указания количества импортирует статью из восьми крупных разделов с несколькими десятками ключевых положений
- **THEN** скил создаёт больше 10 карточек, и каждый из восьми разделов представлен хотя бы одной карточкой

### Requirement: Проверка полноты покрытия
В автоматическом режиме скил MUST перед отправкой сверить список ключевых положений с набором карточек и создать карточки для непокрытых положений. Итоговый отчёт MUST содержать число ключевых положений, число покрытых и разбивку карточек по разделам.

#### Scenario: Все положения покрыты
- **WHEN** импорт в автоматическом режиме завершён
- **THEN** отчёт содержит строку вида «ключевых положений: 34, покрыто: 34» и число карточек по каждому разделу

#### Scenario: Непокрытое положение найдено при сверке
- **WHEN** при сверке выясняется, что для одного из ключевых положений нет карточки
- **THEN** скил создаёт для него карточку до отправки, и в отчёте все положения покрыты

### Requirement: Подтверждение большого набора
Если в автоматическом режиме получилось больше 150 карточек, скил MUST до отправки показать пользователю их число и разбивку по разделам и MUST NOT отправлять карточки без его подтверждения.

#### Scenario: Большой набор
- **WHEN** в автоматическом режиме по очень длинной странице получилось 180 карточек
- **THEN** скил сообщает число и разбивку по разделам, спрашивает подтверждение и ничего не отправляет до ответа
