# Design

## Context

Интерфейс — статичные `index.html`, `styles.css` и `app.js` в `src/main/resources/static/`, их раздаёт Spring Boot. Данные страница получает только через `/api/cards`. Сборка — Gradle (Kotlin DSL). Node в проекте пока не используется, но установлен у разработчика (v26). Выбор Playwright Test (Node) сделан пользователем: он даёт готовое сравнение скриншотов с эталонами (`toHaveScreenshot`), diff-изображения и `--update-snapshots`.

## Goals / Non-Goals

**Goals:**
- Детерминированные скриншоты ключевых состояний страницы, которые не зависят от данных пользователя и от порядка тестов.
- Одна команда Gradle для проверки, она входит в `build`. Ещё одна — для обновления эталонов.
- Автоматическая проверка после правок Claude в файлах интерфейса.

**Non-Goals:**
- Кроссбраузерность и кроссплатформенные эталоны: только Chromium и эталоны для macOS.
- Поведенческие e2e-тесты сценариев `cards-web-ui`.
- CI.

## Decisions

### 1. Playwright Test в `ui-tests/`
Отдельный npm-проект `ui-tests/` (`package.json`, `package-lock.json`, `playwright.config.ts`, `tests/*.spec.ts`). Версия `@playwright/test` фиксируется точно (1.64.x на момент реализации), установка идёт через `npm ci` по lock-файлу. Браузер только Chromium: `npx playwright install chromium`. Эталоны лежат рядом с тестами в `ui-tests/tests/__screenshots__/` и коммитятся.
- *Альтернатива — положить тесты в `src/test/ui`.* Тогда Node-проект смешивается со структурой Gradle, а исходники JUnit — с TypeScript.

### 2. Node скачивает Gradle-плагин `com.github.node-gradle.node`
`node { download = true; version = "24.22.0" }` (текущий LTS), `nodeProjectDir = ui-tests`. Сборка не зависит от того, какой Node установлен у разработчика или будет в CI. Задачи `npmInstall` (`npm ci`) и `NpxTask` даёт сам плагин.
- *Альтернатива — `Exec` с системным `npx`.* Проще, но версия Node у всех разная, а без Node сборка падает с непонятной ошибкой.

### 3. Приложение для тестов запускается через `webServer` Playwright
В `playwright.config.ts` команда `webServer` запускает `java -jar ../build/libs/quiz-1.0-SNAPSHOT.jar --server.port=<порт> --quiz.data-file=<временный файл>`. Порт по умолчанию 18080, переопределяется `QUIZ_UI_TEST_PORT`. Файл данных создаётся в `os.tmpdir()` с уникальным именем. Настройки передаются аргументами командной строки, потому что они имеют приоритет над `application.properties` (см. урок из `RestartPersistenceTest`). Playwright ждёт ответа `GET /api/cards` и останавливает приложение после тестов. Путь к jar передаёт Gradle через переменную окружения `QUIZ_JAR`, а задача `screenshotTest` зависит от `bootJar`.
- *Альтернатива — запускать приложение из Gradle (`bootRun` в фоне).* Неудобно останавливать, и при падении остаются висящие процессы.

### 4. Данные API подменяются в каждом тесте (`page.route`)
Статику (HTML, CSS, JS) отдаёт настоящее приложение, а ответы `/api/cards` каждый тест задаёт сам через `page.route`: фиксированный список карточек, пустой список, ответ 400 с `error`, обрыв сети. Плюсы:
- скриншоты не зависят от случайных `id`, порядка тестов и содержимого файла;
- легко снять состояния ошибок («сервер недоступен»), которые на живом сервере воспроизвести трудно;
- тесты можно запускать параллельно.

Связка «UI + настоящий API» уже покрыта ручной проверкой и тестами `CardApiTest`.
- *Альтернатива — настоящий API с тестовым CSV.* Состояния зависят от порядка тестов, а состояния ошибок не воспроизводятся.

### 5. Набор скриншотов
| Тест | Вьюпорт | Тема |
|---|---|---|
| пустой список | 1280×800 | светлая |
| список из 3 карточек: короткая, многострочная длинная, с HTML-текстом | 1280×800 | светлая |
| тот же список | 1280×800 | тёмная |
| раскрытый ответ у второй карточки | 1280×800 | светлая |
| ошибка валидации формы (ответ 400) | 1280×800 | светлая |
| ошибка загрузки списка (обрыв сети) | 1280×800 | светлая |
| список из 3 карточек | 390×844 (мобильный) | светлая |

Снимается вся страница (`fullPage: true`). Перед снимком тест дожидается конечного состояния, например появления карточек или текста ошибки, а не просто таймаута.

### 6. Стабильность скриншотов
- `toHaveScreenshot` с `animations: "disabled"` и `caret: "hide"`. Допуск `maxDiffPixelRatio: 0.001` на сглаживание шрифтов.
- `deviceScaleFactor: 1`, `locale: "ru-RU"`, фиксированный `colorScheme` в каждом проекте конфигурации.
- Шрифт `system-ui` на разных ОС разный, поэтому имена эталонов содержат платформу (стандартный суффикс Playwright `-chromium-darwin`). Коммитятся эталоны для macOS. Эталоны для Linux и CI — в будущем изменении.
- `workers` не ограничиваются: тесты независимы благодаря решению 4.

### 7. Задачи Gradle
- `playwrightInstall` (`NpxTask`, `playwright install chromium`), зависит от `npmInstall`.
- `screenshotTest` (`NpxTask`, `playwright test`), зависит от `bootJar` и `playwrightInstall`. Входы задачи: `src/main/resources/static/**`, `ui-tests/tests/**` (вместе с эталонами), `ui-tests/playwright.config.ts`, `ui-tests/package-lock.json`, jar. Выход — файл-маркер в `build/`. Если ничего не менялось, задача пропускается как UP-TO-DATE.
- `screenshotUpdate` (`NpxTask`, `playwright test --update-snapshots`) — запускается только вручную, в `check` не входит.
- `tasks.check { dependsOn(screenshotTest) }`, поэтому `./gradlew build` падает при расхождении.
- При падении в сообщении указаны пути к HTML-отчёту `ui-tests/playwright-report/index.html` и к diff-изображениям в `ui-tests/test-results/`. Отчёт открывается через `npx playwright show-report`.

### 8. Хук Claude Code
В `.claude/settings.json` (коммитится, действует для всех, кто работает в репозитории) — хук `PostToolUse` с matcher `Edit|Write|MultiEdit`. Он вызывает скрипт `.claude/hooks/screenshot-check.sh`:
1. читает JSON из stdin и достаёт `tool_input.file_path` через `jq`;
2. если путь не под `src/main/resources/static/`, сразу завершается с кодом 0;
3. иначе запускает `./gradlew screenshotTest -q`;
4. при падении выводит в stderr список упавших тестов и пути к diff-изображениям и завершается с кодом 2: Claude Code передаёт этот вывод Claude как обратную связь.

Таймаут хука — 300 с.
- *Альтернатива — хук на событие `Stop` (один раз в конце ответа).* Меньше запусков, но Claude узнаёт о поломке позже и может сделать несколько правок подряд вслепую. Каждый запуск после первого дешевле за счёт UP-TO-DATE-проверки и прогретого Gradle daemon.

### 9. Правило обновления эталонов
В `CLAUDE.md` записывается правило. Если скриншоты разошлись, Claude не запускает `screenshotUpdate` сам. Исключение — задача, явная цель которой изменить внешний вид. В этом случае Claude перечисляет пользователю изменившиеся скриншоты с путями к diff и обновляет эталоны после подтверждения. В остальных случаях расхождение — регрессия, и исправлять нужно код.

## Risks / Trade-offs

- [Эталоны снимаются на macOS и не совпадут на Linux или в CI] → платформенный суффикс в имени файла. Сейчас коммитятся только эталоны `darwin`, Linux-эталоны (например, через Docker-образ Playwright) — в отдельном изменении вместе с CI.
- [Обновление macOS или Chromium меняет рендеринг шрифтов, и все тесты падают без регрессии] → версия Playwright, а значит и Chromium, зафиксирована. При обновлении ОС эталоны пересоздаются осознанно через `screenshotUpdate` с просмотром diff.
- [`./gradlew build` замедляется] → UP-TO-DATE-проверка по входам. Без изменений интерфейса задача не выполняется.
- [Первый запуск скачивает Node (~30 МБ) и Chromium (~150 МБ)] → разовая операция, всё кэшируется (`.gradle/nodejs`, `~/Library/Caches/ms-playwright`).
- [Хук срабатывает на каждую правку интерфейса (~15–30 с)] → правки вне `static/` фильтруются сразу. Если будет мешать, хук можно перевести на событие `Stop`.
- [Подмена API скрывает расхождение формата API и UI] → формат API зафиксирован спецификацией `cards` и проверяется `CardApiTest`. Поведенческие e2e-тесты на настоящем API — кандидат на отдельное изменение.
- [Порт 18080 занят] → переопределяется `QUIZ_UI_TEST_PORT`. Playwright сообщает о занятом порту понятной ошибкой.

## Migration Plan

Существующие тесты не меняются. Эталоны создаются один раз в задаче 2.x через `screenshotUpdate`, после визуального просмотра. Откат — удалить `ui-tests/`, Node-плагин и задачи из `build.gradle.kts` и хук из `.claude/settings.json`.
