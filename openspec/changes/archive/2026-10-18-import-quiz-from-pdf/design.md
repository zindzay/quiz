# Design

## Context

Изменение повторяет устройство `import-quiz-from-web-page`: скил в `.claude/skills/`, правила генерации в `tools/quiz-import/card-rules.md`, отправка через `tools/quiz-import/post_cards.py` (`check` и `post`). Новое по сравнению с ним — только получение текста из PDF, работа с большими документами и выбор страниц. Требования — в `specs/quiz-from-pdf/spec.md`.

## Goals / Non-Goals

**Goals:**
- Импорт по одной команде: `/quiz-from-pdf <путь> [страницы] [количество]`.
- Ноль новых зависимостей: только то, что даёт macOS с Command Line Tools (python3, swift, PDFKit), — ни Python-пакетов, ни Homebrew.
- Максимальное переиспользование скрипта и правил импорта со страницы.

**Non-Goals:**
- Изменения в `post_cards.py`: его возможностей хватает.
- Извлечение текста скриптом (pypdf, pdftotext, PDFKit): текст и сканы читает Read.
- Кэширование прочитанных документов между вызовами.

## Decisions

### 1. Чтение PDF — встроенный инструмент Read по частям из `split_pdf.swift`
Read в Claude Code читает PDF вместе с текстом и изображениями страниц, поэтому отсканированные страницы распознаются без OCR-библиотек. Но без параметра `pages` он читает документы только до 10 страниц, а `pages` требует `pdftoppm` (poppler), которого на macOS нет. Поэтому выбранный диапазон нарезается на отдельные PDF по 10 страниц, и каждый читается через Read целиком.

Нарезку делает скрипт `tools/quiz-import/split_pdf.swift` на PDFKit (входит в macOS; `swift` — в Command Line Tools, как и `python3`):
```
swift tools/quiz-import/split_pdf.swift FILE [--pages N|N-M] --count N --out DIR
```
- проверяет файл: открывается ли как PDF (иначе код 3), не защищён ли паролем (код 4);
- считает страницы и проверяет диапазон (вне документа — код 1);
- без диапазона при числе страниц больше 100 — код 5 и число страниц в stderr;
- пишет `part-01.pdf`, `part-02.pdf`, … по 10 страниц и `meta.json`: `file`, `pages` (всего в документе), `range`, `parts` (`file`, `from`, `to`, `quota`).
- *Альтернатива — установить poppler.* Внешняя зависимость, которой нет на чистой macOS.
- *Альтернатива — извлекать текстовый слой PDFKit.* Сканы всё равно пришлось бы читать через Read, получились бы две ветки логики.

### 2. Число страниц и защищённые документы
Число страниц и шифрование определяет `split_pdf.swift` через PDFKit — работает и для неиндексированных файлов, где `mdls` возвращает `(null)`. Ограничение в 100 страниц проверяется до чтения документа.
- *Альтернатива — `mdls`/`pdfinfo`.* `mdls` не видит неиндексированные и зашифрованные файлы, `pdfinfo` не установлен по умолчанию.

### 3. Распределение карточек по документу
Квоты частей считает скрипт: каждой части — доля N, пропорциональная числу её страниц (метод наибольших остатков, сумма квот равна N); если частей больше N — N частей, равномерно разнесённых по диапазону, по 1 карточке. Скил читает части по одной и генерирует для каждой её квоту по `card-rules.md`. Так выполняется требование о распределении, и в контексте одновременно не больше 10 страниц.
- *Альтернатива — прочитать весь диапазон и сгенерировать за один раз.* Проще, но модель склонна строить вопросы по началу документа, а контекст переполняется на больших диапазонах.

### 4. Фильтрация служебного текста
В SKILL.md добавляется PDF-специфичное правило поверх `card-rules.md`: игнорировать колонтитулы, номера страниц, оглавление, список литературы и подписи без содержательного текста. Общий файл правил не меняется, чтобы не затронуть скил импорта со страницы.

### 5. Отправка
Без изменений: `post_cards.py check` перед чтением документа, затем JSON во временной директории и `post_cards.py post`. В `allowed-tools`: `Read`, `Write`, `Bash(python3 tools/quiz-import/post_cards.py:*)`, `Bash(swift tools/quiz-import/split_pdf.swift:*)`.

### 6. Тестирование
Дубликаты, частичные ошибки и отчёт уже покрыты автотестами `post_cards.py`. `split_pdf.swift` покрывается тестами `test_split_pdf.py` (запуск скрипта на фикстурах: число страниц, диапазоны, части по 10 страниц, квоты, коды 1/3/4/5). Фикстуры генерирует `tools/quiz-import/fixtures/make_pdfs.swift` — тестовые PDF в `tools/quiz-import/fixtures/`:
- `short.pdf` (2–3 страницы текста),
- `sections.pdf` (около 40 страниц с явными разделами),
- `scanned.pdf` (страницы-изображения),
- `blank.pdf` (пустые страницы),
- `protected.pdf` (с паролем).

Большой документ (более 100 страниц) не коммитится: он генерируется при проверке. Сценарии проверяются вручную на запущенном приложении.

## Risks / Trade-offs

- [Отсканированные страницы плохого качества распознаются с ошибками] → правило «ответ следует из текста» плюс отчёт со списком вопросов. Пользователь видит результат в UI.
- [Чтение 100 страниц расходует много токенов] → лимит в 100 страниц без явного диапазона и чтение частями. Пользователь может сузить диапазон.
- [PDFKit и `swift` есть только на macOS] → проект и так ориентирован на macOS (эталоны скриншотов `-darwin`). Перенос на Linux — отдельное изменение.
- [Первый запуск `swift`-скрипта компилирует его несколько секунд] → приемлемо для импорта, который длится минуты.
- [Тестовые PDF увеличивают репозиторий] → небольшие фикстуры (до 1 МБ в сумме). Большой документ генерируется, а не хранится.
