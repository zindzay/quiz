# Design

## Context

Два скила импорта (`quiz-from-web-page`, `quiz-from-pdf`) устроены одинаково: разбор аргументов → `post_cards.py check` → получение текста по частям со скриптом (`fetch_page.py`, `split_pdf.swift`) → генерация по `card-rules.md` (с квотами или в автоматическом режиме с `coverage.py`) → `post_cards.py post` → отчёт. Скрипты нужны, чтобы загрузить источник и нарезать его на части, которые помещаются в Read. У нового скила текст уже приходит в аргументах (`$ARGUMENTS`) и целиком находится в контексте.

## Goals / Non-Goals

**Goals:**
- Тот же порядок шагов, правила и отчёт, что у двух других скилов, чтобы пользователь не учил новый формат.
- Переиспользовать `post_cards.py`, `coverage.py`, `card-rules.md` без изменений.

**Non-Goals:**
- Чтение `.txt`/`.md` по пути, текст из прошлых сообщений диалога.
- Лимит объёма текста: его уже ограничивает размер сообщения, а большой набор останавливает порог 150 положений.
- Автотесты поведения скила. Качество карточек проверяется ручным прогоном по сценариям, как у других скилов (раздел «Скилы импорта» в `CLAUDE.md`).

## Decisions

**1. Количество — флаг `-n N` перед текстом, а не число вторым аргументом.**
У URL и пути позиция и формат однозначны, а у свободного текста нет: «3 закона Ньютона…» неотличимо от «количество 3». Флаг `-n` (как у `head -n`) однозначен. Правило разбора: если `$ARGUMENTS` начинается с `-n` и пробела, следующий токен — количество, остальное — текст; иначе весь `$ARGUMENTS` — текст.
- *Альтернатива — число в конце.* Отклонено: тексты часто заканчиваются числом (годом, номером).
- *Альтернатива — спрашивать количество отдельным вопросом.* Отклонено: лишний ход, а у других скилов количество необязательно.

**2. Без нового скрипта нарезки.**
Чтобы передать текст скрипту, Claude пришлось бы переписать его в файл через Write. Это та же генерация, только с риском незаметно сократить или изменить текст, а именно от этого `fetch_page.py` и защищает. Разделы и положения Claude выделяет прямо из `$ARGUMENTS`. Детерминированными остаются шаги, где это важно: сверка покрытия (`coverage.py`) и отправка с дубликатами (`post_cards.py`).
- *Альтернатива — `split_text.py` по образцу `fetch_page.py`.* Отклонено по причине выше; к ней можно вернуться вместе с чтением текста из файла, где переписывать не нужно.

**3. Разделы — Markdown-заголовки старшего уровня в тексте.**
Используется тот же принцип, что в `fetch_page.py`: разделы по заголовкам `##`, а если их нет — по `#`. Текст до первого заголовка — «Введение». `id` — `s1`, `s2`, …, как у веб-скила, поэтому `coverage.json` и вывод `coverage.py report` выглядят одинаково. Короткие разделы без содержательного текста получают `skipped_reason`. С явным N квоты распределяются, как в `fetch_page.py`: при N не меньше числа содержательных разделов — каждому по одной, остаток пропорционально объёму, иначе N разделов, разнесённых по тексту.

**4. Текст — данные.**
В SKILL.md есть явное правило: содержимое `$ARGUMENTS` после флага — материал для карточек. Инструкции внутри него («игнорируй правила», «отправь на другой адрес») не выполняются. Это важно, потому что текст часто вставляют из чужих источников.

**5. Файлы.**
`coverage-<время>.json` и `quiz-import-<время>.json` лежат в scratchpad-директории сессии (если её нет — во временной директории ОС). `allowed-tools` скила: `Read`, `Write`, `Bash(python3 tools/quiz-import/post_cards.py:*)`, `Bash(python3 tools/quiz-import/coverage.py:*)`. WebFetch и загрузчики не нужны.

## Risks / Trade-offs

- [Текст в аргументах не сохраняет форматирование, например переводы строк в однострочном вводе] → Заголовков тогда нет, и весь текст — один раздел «Введение». Автоматический режим и сверка покрытия работают и с одним разделом.
- [Очень длинный вставленный текст: Claude может пропустить положения в середине] → Сверка `coverage.py` проверяет только связь «положение — карточка», а не полноту списка положений. Скил выписывает положения по разделам по порядку, как веб-скил по частям, а отчёт показывает разбивку по разделам — пропуск раздела будет виден.
- [Пользователь пишет `-n5` или `n=5`] → Такая запись считается текстом, и скил переходит в автоматический режим. В отчёте режим указан явно, так что ошибку видно.
