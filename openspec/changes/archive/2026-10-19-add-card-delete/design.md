# Design

## Context

Страница `/cards.html` строит список из шаблона: элемент `li.card.quiz-card` целиком имеет `role="button"`, `tabindex="0"` и `aria-expanded` и раскрывает ответ по клику, Enter и Пробел. e2e-тесты ищут карточки как `getByRole('list').getByRole('button')`. Хранилище — `CsvCardRepository` (всё в памяти, атомарная перезапись файла под `ReadWriteLock`), методы `save` и `update`. Удаления нет ни в API, ни в интерфейсе. Требования — delta-спецификации `cards` и `cards-web-ui` этого изменения.

## Goals / Non-Goals

**Goals:**
- Удаление одной карточки из списка с подтверждением на самой карточке.
- Доступность: у раскрытия ответа и удаления — отдельные элементы, клавиатура работает как раньше.

**Non-Goals:**
- Отмена удаления, корзина, массовое удаление, редактирование.
- Изменение формата CSV.

## Decisions

### 1. API — `DELETE /api/cards/{id}`
`CardRepository.delete(String id)` возвращает `boolean`: удалена ли карточка. `CsvCardRepository` под блокировкой записи строит список без карточки, атомарно перезаписывает файл и только потом меняет список в памяти — как в `save` и `update`. `CardService.delete(id)` бросает `CardNotFoundException`, если карточки нет. Контроллер отвечает `204 No Content`; 404 даёт существующий `ApiExceptionHandler`. Удалённая карточка исчезает и из случайной выборки, потому что выборка строится по `findAll`.
- *Альтернатива — мягкое удаление (флаг `deleted`).* Позволило бы «Вернуть», но меняет формат CSV и требует фильтрации везде; отмена вне рамок.

### 2. Разметка элемента списка
Вложенные интерактивные элементы недопустимы: кнопка «Удалить» внутри `li role="button"` нарушает доступность, а её клик раскрывал бы ответ. Новая разметка:

```html
<li class="card quiz-card">
  <div class="card-body">
    <div class="quiz-toggle" role="button" tabindex="0" aria-expanded="false">
      <p class="quiz-question">…</p>
      <p class="quiz-answer">…</p>
    </div>
    <div class="quiz-card-actions">
      <button type="button">Удалить</button>
      <span class="quiz-confirm" hidden>Удалить карточку? <button>Да</button> <button>Отмена</button></span>
      <p class="quiz-delete-error" role="alert" hidden></p>
    </div>
  </div>
</li>
```

Раскрытие (`role="button"`, `aria-expanded`, Enter и Пробел) переезжает с `li` на `.quiz-toggle`. Класс `revealed` остаётся на `li`, поэтому стили ответа не меняются. Кнопки удаления — небольшие `btn btn-sm` (`btn-outline-danger` для «Удалить», `btn-danger` для «Да», `btn-outline-secondary` для «Отмена»), справа внизу карточки.

**Поиск карточек в e2e** меняется: в списке теперь есть кнопки «Удалить», поэтому карточки ищутся как элементы списка `getByRole('list').getByRole('listitem')`, а раскрытие — как кнопка с текстом вопроса внутри элемента. `CLAUDE.md` обновляется.

### 3. Поведение удаления в `cards.js`
- «Удалить» → скрыть её, показать подтверждение и перевести фокус на «Отмена» (безопасный выбор по умолчанию).
- «Отмена» → скрыть подтверждение, вернуть «Удалить» и фокус на неё.
- «Да» → заблокировать кнопки и выполнить `DELETE`:
  - при ответе 204 (или 404 — карточку уже удалили в другой вкладке, результат тот же) — удалить `li` и, если список опустел, показать сообщение о пустом списке;
  - при сетевой ошибке или другом статусе — скрыть подтверждение, вернуть «Удалить» и показать на карточке «Не удалось удалить карточку. Проверьте, что сервер запущен, и попробуйте ещё раз.».

### 4. Тестирование
- **JUnit:**
  - `CsvCardRepositoryTest` — удаление сохраняется в файле, порядок остальных не меняется, удаление несуществующего возвращает `false` без перезаписи;
  - `CardServiceTest` — удаление и `CardNotFoundException`;
  - `CardApiTest` — 204, список без карточки, 404, удалённая карточка на повторении не попадает в `random`;
  - `RestartPersistenceTest` — удаление переживает перезапуск.
- **E2E** (`cards-list.spec.ts`):
  - все сценарии требований «Удаление карточки в списке» и «Ошибка удаления карточки»;
  - существующие сценарии переводятся на новый поиск карточек.
- **Скриншоты** (`ui-tests/tests/cards-list.spec.ts`): существующие снимки списка меняются (кнопки «Удалить»); новые — подтверждение и ошибка удаления. Эталоны снимаются после того, как пользователь просмотрит новые скриншоты.

## Risks / Trade-offs

- [Удаление необратимо] → подтверждение на карточке, фокус по умолчанию на «Отмена». Отмена удаления — отдельное изменение, если понадобится.
- [Карточку удалили, пока она в идущем тесте в другой вкладке] → `PUT .../review` вернёт 404, и страница теста покажет существующую ошибку сохранения ответа. Тест можно начать заново; отдельной обработки этого случая нет.
- [Смена разметки ломает поиск карточек в тестах] → поиск обновляется в том же изменении, правило записывается в `CLAUDE.md`.
- [Скриншоты списка меняются] → эталоны обновляются только после подтверждения пользователя.
