# quiz-from-pdf Specification

## Purpose

Скил Claude Code, который по локальному PDF-файлу составляет набор карточек «вопрос — ответ» по его содержанию и добавляет их в запущенное приложение quiz.

## Requirements

### Requirement: Вызов скила
Скил SHALL принимать обязательный путь к локальному PDF-файлу, необязательный диапазон страниц (`N` или `N-M`) и необязательное количество карточек от 1 до 50, по умолчанию 10. Если файла нет, он не PDF, диапазон некорректен или выходит за число страниц, скил MUST сообщить об ошибке до генерации карточек.

#### Scenario: Вызов с путём
- **WHEN** пользователь вызывает скил с путём `docs/lecture.pdf` на 8 страниц
- **THEN** скил генерирует до 10 карточек по всему документу

#### Scenario: Вызов с диапазоном и количеством
- **WHEN** пользователь вызывает скил с путём, диапазоном `3-5` и количеством 6
- **THEN** скил генерирует не больше 6 карточек только по страницам 3–5

#### Scenario: Неверные аргументы
- **WHEN** путь указывает на несуществующий файл или на `.txt`, либо диапазон `10-20` при 8 страницах
- **THEN** скил сообщает об ошибке и не отправляет карточки

### Requirement: Проверка доступности приложения
Перед чтением документа скил MUST проверить, что API приложения отвечает по базовому адресу (по умолчанию `http://localhost:8080`, переопределяется `QUIZ_API_URL`). Если API недоступно, скил MUST остановиться и подсказать, как запустить приложение.

#### Scenario: Приложение не запущено
- **WHEN** по базовому адресу никто не отвечает
- **THEN** скил сообщает, что приложение недоступно, предлагает выполнить `./gradlew bootRun` и не читает документ

### Requirement: Ограничение объёма
Если диапазон не указан, а в документе больше 100 страниц, скил MUST NOT обрабатывать документ целиком: он MUST сообщить число страниц и попросить указать диапазон не больше 100 страниц.

#### Scenario: Большой документ без диапазона
- **WHEN** пользователь передаёт PDF на 300 страниц без диапазона
- **THEN** скил сообщает, что в документе 300 страниц, просит указать диапазон и не генерирует карточки

### Requirement: Генерация карточек по содержимому документа
Скил SHALL строить карточки только по тексту выбранных страниц, включая отсканированные. Колонтитулы, номера страниц и оглавление MUST NOT становиться предметом вопросов. Карточки MUST быть распределены по всему выбранному диапазону, а не сосредоточены в его начале. Правила качества и языка MUST совпадать с `quiz-from-web-page`.

#### Scenario: Распределение по документу
- **WHEN** скил генерирует 10 карточек по документу из 40 страниц с несколькими разделами
- **THEN** карточки касаются разных разделов документа, а не только первых страниц

#### Scenario: Отсканированный документ
- **WHEN** PDF состоит из отсканированных страниц без текстового слоя
- **THEN** скил распознаёт текст со страниц и генерирует карточки по нему

### Requirement: Недостаточно содержимого
Если документ нельзя прочитать (повреждён, защищён паролем) или на выбранных страницах нет осмысленного текста, скил MUST сообщить причину и MUST NOT отправлять карточки. Если текста хватает только на часть запрошенных карточек, скил SHALL создать меньше и сообщить об этом.

#### Scenario: Защищённый документ
- **WHEN** PDF защищён паролем
- **THEN** скил сообщает, что не может прочитать документ, и в приложение ничего не добавляется

#### Scenario: Пустые страницы
- **WHEN** выбранный диапазон содержит только изображения без текста или пустые страницы
- **THEN** скил сообщает, что текста для карточек нет, и ничего не отправляет

### Requirement: Отправка, дубликаты и отчёт
Скил MUST пропускать карточки с вопросами, которые уже есть в приложении или повторяются в наборе (без учёта регистра и пробелов по краям). Каждую новую карточку он SHALL отправлять отдельным `POST /api/cards`, не прерываясь при ошибке одной из них. В конце скил MUST вывести число добавленных, пропущенных и неудавшихся карточек и список добавленных вопросов.

#### Scenario: Повторный импорт
- **WHEN** пользователь второй раз импортирует тот же PDF, и скил генерирует вопросы, которые уже есть
- **THEN** такие карточки не отправляются и учитываются в отчёте как пропущенные

#### Scenario: Успешный импорт
- **WHEN** все сгенерированные карточки новые и API принимает их
- **THEN** карточки появляются в `GET /api/cards`, а отчёт перечисляет их вопросы
