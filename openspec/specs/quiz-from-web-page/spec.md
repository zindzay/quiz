# quiz-from-web-page Specification

## Purpose

Скил Claude Code, который по ссылке на веб-страницу составляет набор карточек «вопрос — ответ» по её содержанию и добавляет их в запущенное приложение quiz.

## Requirements

### Requirement: Вызов скила
Скил SHALL принимать обязательный URL страницы (http или https) и необязательное количество карточек от 1 до 50, по умолчанию 10. При отсутствии или неверном URL, а также при количестве вне диапазона скил MUST сообщить об ошибке до каких-либо сетевых запросов.

#### Scenario: Вызов с URL
- **WHEN** пользователь вызывает скил с URL `https://example.com/article`
- **THEN** скил генерирует до 10 карточек по этой странице

#### Scenario: Вызов с количеством
- **WHEN** пользователь вызывает скил с URL и количеством 5
- **THEN** скил генерирует не больше 5 карточек

#### Scenario: Неверные аргументы
- **WHEN** пользователь передаёт `ftp://example.com` или количество 100
- **THEN** скил сообщает об ошибке и не загружает страницу

### Requirement: Проверка доступности приложения
Перед загрузкой страницы скил MUST проверить, что API приложения отвечает по базовому адресу (по умолчанию `http://localhost:8080`, переопределяется переменной окружения `QUIZ_API_URL`). Если API недоступно, скил MUST остановиться и подсказать, как запустить приложение.

#### Scenario: Приложение не запущено
- **WHEN** по базовому адресу никто не отвечает
- **THEN** скил сообщает, что приложение недоступно, предлагает выполнить `./gradlew bootRun` и не генерирует карточки

### Requirement: Генерация карточек по содержимому страницы
Скил SHALL строить карточки только по основному тексту страницы, без навигации, рекламы и комментариев. Каждая карточка MUST проверять один факт или понятие из текста, ответ MUST следовать из текста страницы. Карточки MUST быть на языке страницы, а длина вопроса и ответа MUST NOT превышать 2000 символов.

#### Scenario: Карточки по статье
- **WHEN** скил обрабатывает статью о протоколе HTTP
- **THEN** каждый вопрос касается содержания статьи, а ответ на него есть в тексте статьи

#### Scenario: Язык карточек
- **WHEN** страница написана на русском
- **THEN** вопросы и ответы сгенерированы на русском

### Requirement: Недостаточно содержимого
Если страницу не удалось загрузить или в ней нет осмысленного текста (ошибка HTTP, пустая страница, контент только через JavaScript), скил MUST сообщить причину и MUST NOT отправлять карточки. Если текста хватает только на часть запрошенных карточек, скил SHALL создать меньше и сообщить об этом.

#### Scenario: Страница недоступна
- **WHEN** страница отвечает 404
- **THEN** скил сообщает об ошибке загрузки, и в приложение ничего не добавляется

#### Scenario: Короткая страница
- **WHEN** запрошено 20 карточек, а на странице всего два абзаца
- **THEN** скил создаёт меньше карточек и указывает в итоге, что материала было недостаточно

### Requirement: Пропуск дубликатов
Перед отправкой скил MUST получить текущие карточки приложения и MUST NOT отправлять карточку, вопрос которой совпадает с уже существующим (без учёта регистра и пробелов по краям) или с другой карточкой из того же набора.

#### Scenario: Вопрос уже есть
- **WHEN** в приложении уже есть карточка с вопросом «Что такое HTTP?», а скил сгенерировал вопрос « что такое http? »
- **THEN** эта карточка не отправляется и учитывается в итоге как пропущенная

### Requirement: Отправка и итоговый отчёт
Скил SHALL отправлять каждую новую карточку отдельным запросом `POST /api/cards`. Ошибка одной карточки MUST NOT останавливать отправку остальных. В конце скил MUST вывести число добавленных, пропущенных и неудавшихся карточек, а также список добавленных вопросов.

#### Scenario: Частичная ошибка
- **WHEN** одна из 10 карточек отклонена API с кодом 400
- **THEN** остальные 9 добавлены, а в отчёте указаны 9 добавленных, 1 неудавшаяся и сообщение `error` из ответа

#### Scenario: Успешный импорт
- **WHEN** все сгенерированные карточки новые и API принимает их
- **THEN** карточки появляются в `GET /api/cards`, а отчёт перечисляет их вопросы
