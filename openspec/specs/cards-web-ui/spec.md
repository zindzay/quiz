# cards-web-ui Specification

## Purpose

Браузерный интерфейс, через который пользователь просматривает карточки «вопрос — ответ» и добавляет новые без прямых обращений к API.

## Requirements

### Requirement: Главная страница
Приложение SHALL отдавать по адресу `/` HTML-страницу, которая загружает карточки через API и показывает их список в порядке добавления.

#### Scenario: Открытие страницы
- **WHEN** пользователь открывает `/` в браузере, а в хранилище есть карточки
- **THEN** страница показывает вопрос каждой карточки

#### Scenario: Нет карточек
- **WHEN** пользователь открывает `/`, а карточек нет
- **THEN** страница показывает сообщение о том, что карточек пока нет

### Requirement: Раскрытие ответа
В списке ответ каждой карточки SHALL быть изначально скрыт и MUST показываться по нажатию на карточку. Повторное нажатие MUST снова скрывать ответ.

#### Scenario: Показ и скрытие ответа
- **WHEN** пользователь нажимает на карточку со скрытым ответом
- **THEN** ответ этой карточки становится видимым, а ответы других карточек остаются скрытыми
- **AND** повторное нажатие на ту же карточку снова скрывает ответ

### Requirement: Форма добавления карточки
Страница SHALL содержать форму с полями «Вопрос» и «Ответ» и кнопкой добавления. После успешного создания новая карточка MUST появиться в конце списка без перезагрузки страницы, а поля формы MUST очиститься.

#### Scenario: Успешное добавление
- **WHEN** пользователь заполняет оба поля и нажимает «Добавить»
- **THEN** карточка сохраняется, появляется в конце списка, а поля формы очищаются

### Requirement: Ошибки при добавлении
Если сервер отклонил создание карточки или недоступен, страница MUST показать пользователю сообщение об ошибке и MUST сохранить введённый в форму текст.

#### Scenario: Пустое поле
- **WHEN** пользователь отправляет форму с пустым вопросом
- **THEN** страница показывает сообщение об ошибке, карточка не добавляется, а введённый ответ остаётся в форме

### Requirement: Безопасный вывод текста
Текст вопросов и ответов MUST отображаться как обычный текст: HTML-разметка в нём MUST NOT интерпретироваться браузером.

#### Scenario: HTML в тексте карточки
- **WHEN** карточка содержит вопрос `<b>жирный</b><script>alert(1)</script>`
- **THEN** страница показывает этот текст буквально, и скрипт не выполняется

### Requirement: Тема оформления по системной настройке
Страница SHALL использовать тёмную тему, если в операционной системе или браузере пользователя выбрана тёмная тема, и светлую тему во всех остальных случаях. Текст, поля ввода, кнопки, карточки и сообщения об ошибках MUST оставаться читаемыми в обеих темах.

#### Scenario: Тёмная системная тема
- **WHEN** пользователь с тёмной системной темой открывает страницу
- **THEN** страница отображается в тёмной теме

#### Scenario: Светлая системная тема
- **WHEN** пользователь со светлой системной темой открывает страницу
- **THEN** страница отображается в светлой теме

### Requirement: Работа без внешних ресурсов
Страница MUST загружать стили, скрипты и шрифты только с сервера приложения и MUST NOT обращаться к сторонним доменам (CDN, сервисы шрифтов).

#### Scenario: Нет запросов к сторонним доменам
- **WHEN** пользователь открывает страницу
- **THEN** все запросы, которые делает страница, идут на адрес сервера приложения

#### Scenario: Работа без доступа в интернет
- **WHEN** приложение запущено на компьютере без доступа в интернет, и пользователь открывает страницу локально
- **THEN** страница отображается полностью оформленной, и все сценарии работают
