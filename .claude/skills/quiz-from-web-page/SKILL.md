# Карточки по веб-странице

Аргументы: `$ARGUMENTS` — URL страницы и, необязательно, количество карточек.

Все команды выполняются из корня репозитория. Требования — `openspec/specs/quiz-from-web-page/spec.md`.

## 1. Разобрать аргументы — до любых сетевых запросов

- Первый аргумент — URL. Он обязателен и должен начинаться с `http://` или `https://`.
- Второй аргумент — количество карточек, целое число от 1 до 50. Если не указан — **10**.
- Если URL отсутствует, у него другая схема (`ftp://`, `file://`, без схемы) или количество вне 1–50 / не число — **сообщи пользователю, что именно не так, и остановись**. Ничего не загружай и не вызывай скрипт.

## 2. Проверить, что приложение запущено

```bash
python3 tools/quiz-import/post_cards.py check
```

- Код 0 — продолжай.
- Код 2 — **остановись**: передай пользователю сообщение скрипта (приложение недоступно, запустить `./gradlew bootRun`). Страницу не загружай, карточки не генерируй.

Адрес API берётся из `QUIZ_API_URL`, по умолчанию `http://localhost:8080`.

## 3. Загрузить страницу

Вызови WebFetch с этим URL и запросом:

> Верни основной текст страницы дословно, без пересказа и сокращений: заголовки, абзацы, списки, таблицы, примеры кода. Не включай навигацию, меню, рекламу, комментарии, футер, cookie-баннеры, блоки «читайте также». Если основного текста нет или страница не загрузилась — так и напиши.

**Остановись без отправки карточек**, если:
- WebFetch вернул ошибку (404, 5xx, таймаут, недоступный хост);
- осмысленного текста нет: пустая страница, только навигация, заглушка «включите JavaScript», страница входа.

Сообщи пользователю причину. В приложение ничего не добавляется.

Если WebFetch сообщил, что содержимое сокращено, — продолжай, но в итоговом отчёте предупреди, что карточки построены по доступной части страницы.

## 4. Сгенерировать карточки

1. Прочитай `tools/quiz-import/card-rules.md` и следуй ему полностью.
2. Сгенерируй **не больше** запрошенного количества карточек. Если материала хватает только на часть — сделай меньше и запомни это для отчёта.
3. Запиши результат JSON-массивом `[{"question": ..., "answer": ...}]` в файл `quiz-import-<время>.json` в scratchpad-директории сессии (если её нет — во временной директории ОС).

## 5. Отправить карточки

```bash
python3 tools/quiz-import/post_cards.py post <путь к JSON>
```

Скрипт сам пропускает вопросы, которые уже есть в приложении или повторяются в наборе, отправляет остальные по одной и печатает JSON-отчёт `added` / `skipped` / `failed`. Ошибка одной карточки не останавливает остальные. Код 2 — приложение остановилось между шагами: сообщи об этом пользователю.

## 6. Отчёт пользователю

Кратко, по-русски:

- источник: URL и заголовок страницы;
- **добавлено N**, **пропущено M** (уже были в приложении), **не удалось K**;
- список добавленных вопросов;
- для неудавшихся — вопрос и сообщение `error`;
- если карточек меньше запрошенного — что материала на странице недостаточно;
- если страница была сокращена — предупреждение из шага 3.

Карточки видны на http://localhost:8080 (или по адресу из `QUIZ_API_URL`).
