# Карточки по веб-странице

Аргументы: `$ARGUMENTS` — URL страницы и, необязательно, количество карточек.

Все команды выполняются из корня репозитория. Требования — `openspec/specs/quiz-from-web-page/spec.md`.

## 1. Разобрать аргументы — до любых сетевых запросов

- Первый аргумент — URL. Он обязателен и должен начинаться с `http://` или `https://`.
- Второй аргумент — количество карточек, целое число от 1 до 50. Если не указан — **10**.
- Если URL отсутствует, у него другая схема (`ftp://`, `file://`, без схемы) или количество вне 1–50 / не число — **сообщи пользователю, что именно не так, и остановись**. Ничего не загружай и не вызывай скрипт.

## 2. Проверить, что приложение запущено

```bash
python3 tools/quiz-import/post_cards.py check
```

- Код 0 — продолжай.
- Код 2 — **остановись**: передай пользователю сообщение скрипта (приложение недоступно, запустить `./gradlew bootRun`). Страницу не загружай, карточки не генерируй.

Адрес API берётся из `QUIZ_API_URL`, по умолчанию `http://localhost:8080`.

## 3. Загрузить полный текст страницы

Каталог для результата — `page-<время>` в scratchpad-директории сессии (если её нет — во временной директории ОС):

```bash
python3 tools/quiz-import/fetch_page.py "<URL>" --count <N> --out <каталог>
```

Скрипт сам загружает HTML, выделяет основной текст без пересказа (без навигации, меню, футера, скриптов), делит его на крупные разделы и части до ~12 000 символов и распределяет N карточек по разделам. Результат — `<каталог>/meta.json` и `<каталог>/chunk-01.md`, `chunk-02.md`, …

По коду выхода:
- **0** — прочитай `meta.json` и переходи к шагу 4.
- **4** — страница не загрузилась (HTTP-ошибка, недоступный хост, не HTML). **Остановись**: передай пользователю сообщение скрипта из stderr. Карточки не генерируй, в приложение ничего не добавляется. Запасной путь при этом коде не используется: сайт явно отказал.
- **3** — в HTML меньше 500 символов текста (страница собирается JavaScript) — переходи к запасному пути, шаг 3а.
- **1** — ошибка аргументов: сообщи пользователю текст ошибки и остановись.

`meta.json`:
- `title`, `total_chars` — объём основного текста, `processed_chars` — сколько обработано, `truncated` — текст длиннее 500 000 символов и обработано только начало;
- `sections` — крупные разделы по порядку: `id`, `title`, `chars`, `chunks` (номера частей раздела), `quota` (сколько карточек сделать по разделу), `skipped_reason` (справочный или короткий раздел — карточек по нему не делать);
- `chunks` — части: `file`, `chars`, `sections` (`id` разделов в части).

## 3а. Запасной путь: страница без статического текста

Только при коде 3. Вызови WebFetch с этим URL и запросом:

> Верни основной текст страницы дословно, без пересказа и сокращений: заголовки, абзацы, списки, таблицы, примеры кода. Не включай навигацию, меню, рекламу, комментарии, футер, cookie-баннеры, блоки «читайте также». Если основного текста нет или страница не загрузилась — так и напиши.

Если результат сообщает, что текст продолжается, повторяй вызов с `offset` из предыдущего результата, пока страница не закончится.

- Осмысленного текста нет (пустая страница, заглушка «включите JavaScript», страница входа) — **остановись**, сообщи причину, ничего не отправляй.
- Иначе сгенерируй до N карточек по полученному тексту по `card-rules.md`, равномерно по всему тексту, и переходи к шагу 5. В отчёте обязательно предупреди: «текст получен через WebFetch в обработанном виде — полнота не гарантируется». Строку покрытия не выводи.

## 4. Сгенерировать карточки по частям

1. Прочитай `tools/quiz-import/card-rules.md` и следуй ему полностью.
2. Читай части **по одной, по порядку** (`Read` файла `chunk-XX.md`). Для каждой части:
   - для каждого раздела части с `quota > 0` сделай **ровно** `quota` карточек по тексту этого раздела. Если раздел занимает несколько частей (`chunks` из нескольких номеров), раздели его квоту между этими частями примерно пропорционально объёму, чтобы в сумме вышла `quota`;
   - если в разделе материала меньше квоты — сделай меньше и запомни это для отчёта;
   - по разделам с `skipped_reason` карточки не делай;
   - не повторяй вопросы из предыдущих частей;
   - запоминай, сколько карточек дал каждый раздел.
3. Общее число карточек не превышает N.
4. Запиши все карточки одним JSON-массивом `[{"question": ..., "answer": ...}]` в файл `quiz-import-<время>.json` рядом с каталогом страницы.

## 5. Отправить карточки

```bash
python3 tools/quiz-import/post_cards.py post <путь к JSON>
```

Скрипт сам пропускает вопросы, которые уже есть в приложении или повторяются в наборе, отправляет остальные по одной и печатает JSON-отчёт `added` / `skipped` / `failed`. Ошибка одной карточки не останавливает остальные. Код 2 — приложение остановилось между шагами: сообщи об этом пользователю.

## 6. Отчёт пользователю

Кратко, по-русски:

- источник: URL и заголовок страницы;
- **добавлено N**, **пропущено M** (уже были в приложении), **не удалось K**;
- список добавленных вопросов;
- для неудавшихся — вопрос и сообщение `error`;
- **покрытие** (кроме запасного пути): строка `обработано <processed_chars> из <total_chars> символов (<P> %)`, числа с пробелом между разрядами, P — доля, округлённая вниз до целого (100 % только при полном тексте);
- **разделы**: каждый раздел, давший карточки, с их числом; отдельной строкой — пропущенные разделы с причиной (`skipped_reason`);
- если карточек меньше запрошенного — по каким разделам не хватило материала;
- если `truncated` — предупреждение: страница длиннее 500 000 символов, обработано начало, не обработано `<100 − P>` % текста;
- для запасного пути — предупреждение из шага 3а.

Карточки видны на http://localhost:8080 (или по адресу из `QUIZ_API_URL`).
