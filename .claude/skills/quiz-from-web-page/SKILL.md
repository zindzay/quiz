# Карточки по веб-странице

Аргументы: `$ARGUMENTS` — URL страницы и, необязательно, количество карточек.

Два режима:
- **явное количество N** — до N карточек, распределённых по разделам (шаг 4);
- **автоматический** (количество не указано) — карточка на каждое ключевое положение страницы, число карточек определяет содержание, с проверкой полноты (шаг 4А).

Все команды выполняются из корня репозитория. Требования — `openspec/specs/quiz-from-web-page/spec.md`.

## 1. Разобрать аргументы — до любых сетевых запросов

- Первый аргумент — URL. Он обязателен и должен начинаться с `http://` или `https://`.
- Второй аргумент — количество карточек, целое число от 1 до 50. Если не указан — **автоматический режим**.
- Если URL отсутствует, у него другая схема (`ftp://`, `file://`, без схемы) или количество вне 1–50 / не число — **сообщи пользователю, что именно не так, и остановись**. Ничего не загружай и не вызывай скрипт.

## 2. Проверить, что приложение запущено

```bash
python3 tools/quiz-import/post_cards.py check
```

- Код 0 — продолжай.
- Код 2 — **остановись**: передай пользователю сообщение скрипта (приложение недоступно, запустить `./gradlew bootRun`). Страницу не загружай, карточки не генерируй.

Адрес API берётся из `QUIZ_API_URL`, по умолчанию `http://localhost:8080`.

## 3. Загрузить полный текст страницы

Каталог для результата — `page-<время>` в scratchpad-директории сессии (если её нет — во временной директории ОС):

```bash
python3 tools/quiz-import/fetch_page.py "<URL>" --count <N или auto> --out <каталог>
```

Скрипт сам загружает HTML, выделяет основной текст без пересказа (без навигации, меню, футера, скриптов), делит его на крупные разделы и части до ~12 000 символов и распределяет N карточек по разделам (в автоматическом режиме `--count auto` квоты не считаются: `quota: null`). Результат — `<каталог>/meta.json` и `<каталог>/chunk-01.md`, `chunk-02.md`, …

По коду выхода:
- **0** — прочитай `meta.json` и переходи к шагу 4 (явное количество) или 4А (автоматический режим).
- **4** — страница не загрузилась (HTTP-ошибка, недоступный хост, не HTML). **Остановись**: передай пользователю сообщение скрипта из stderr. Карточки не генерируй, в приложение ничего не добавляется. Запасной путь при этом коде не используется: сайт явно отказал.
- **3** — в HTML меньше 500 символов текста (страница собирается JavaScript) — переходи к запасному пути, шаг 3а.
- **1** — ошибка аргументов: сообщи пользователю текст ошибки и остановись.

`meta.json`:
- `title`, `total_chars` — объём основного текста, `processed_chars` — сколько обработано, `truncated` — текст длиннее 500 000 символов и обработано только начало;
- `sections` — крупные разделы по порядку: `id`, `title`, `chars`, `chunks` (номера частей раздела), `quota` (сколько карточек сделать по разделу), `skipped_reason` (справочный или короткий раздел — карточек по нему не делать);
- `chunks` — части: `file`, `chars`, `sections` (`id` разделов в части).

## 3а. Запасной путь: страница без статического текста

Только при коде 3. Вызови WebFetch с этим URL и запросом:

> Верни основной текст страницы дословно, без пересказа и сокращений: заголовки, абзацы, списки, таблицы, примеры кода. Не включай навигацию, меню, рекламу, комментарии, футер, cookie-баннеры, блоки «читайте также». Если основного текста нет или страница не загрузилась — так и напиши.

Если результат сообщает, что текст продолжается, повторяй вызов с `offset` из предыдущего результата, пока страница не закончится.

- Осмысленного текста нет (пустая страница, заглушка «включите JavaScript», страница входа) — **остановись**, сообщи причину, ничего не отправляй.
- Иначе с явным количеством сгенерируй до N карточек по полученному тексту по `card-rules.md`, равномерно по всему тексту, и переходи к шагу 4Б. В автоматическом режиме выполни шаг 4А, считая разделами заголовки полученного текста (`id` `s1`, `s2`, …; текст до первого заголовка — «Введение»). В отчёте обязательно предупреди: «текст получен через WebFetch в обработанном виде — полнота не гарантируется». Строку покрытия не выводи.

## 4. Явное количество: карточки по квотам

1. Прочитай `tools/quiz-import/card-rules.md` и следуй ему полностью.
2. Читай части **по одной, по порядку** (`Read` файла `chunk-XX.md`). Для каждой части:
   - для каждого раздела части с `quota > 0` сделай **ровно** `quota` карточек по тексту этого раздела. Если раздел занимает несколько частей (`chunks` из нескольких номеров), раздели его квоту между этими частями примерно пропорционально объёму, чтобы в сумме вышла `quota`;
   - если в разделе материала меньше квоты — сделай меньше и запомни это для отчёта;
   - по разделам с `skipped_reason` карточки не делай;
   - не повторяй вопросы из предыдущих частей;
   - запоминай, сколько карточек дал каждый раздел.
3. Общее число карточек не превышает N.
4. Запиши все карточки одним JSON-массивом `[{"question": ..., "answer": ...}]` в файл `quiz-import-<время>.json` рядом с каталогом страницы. Переходи к шагу 4Б.

## 4А. Автоматический режим: полный охват

Прочитай `tools/quiz-import/card-rules.md` целиком, включая раздел «Полный охват (автоматический режим)», и следуй ему. Файлы — рядом с каталогом страницы: `coverage-<время>.json` и `quiz-import-<время>.json`.

1. **Положения.** Читай части **по одной, по порядку** (`Read` файла `chunk-XX.md`) и выписывай ключевые положения каждого раздела части в `coverage.json` (формат — `card-rules.md`): разделы — из `meta.json` с теми же `id` и `title`, у всех положений `card: null`. Разделы со `skipped_reason` переноси с ним и пустыми `points`. Раздел на нескольких частях дополняй, а не заводи заново. Повтор уже выписанного положения не добавляй.
2. **Порог 150 — до генерации карточек.** Карточек будет столько же, сколько положений. Если положений больше 150:
   - запиши `[]` в файл карточек и выполни `python3 tools/quiz-import/coverage.py report <coverage> <карточки>`;
   - покажи пользователю число положений и разбивку по разделам из отчёта и спроси: **отправить все**, **отменить** или **указать количество** (1–50, тогда скил выполняется заново с этим числом, шаг 4);
   - **заверши ход вопросом** и ничего не генерируй и не отправляй до ответа. «Отменить» — остановись, ничего не отправлено.
3. **Карточки.** По каждому положению сделай одну карточку по `card-rules.md`; ответ должен следовать из текста положения (если без контекста не сформулировать — перечитай часть). Карточки — в один JSON-массив, индекс карточки — в `card` положения. Повторяющиеся положения ссылаются на одну карточку.
4. **Сверка.** `python3 tools/quiz-import/coverage.py check <coverage> <карточки>`:
   - **0** — всё покрыто, переходи к шагу 4Б;
   - **3** — в stdout JSON с пробелами. `uncovered` — сделай карточки для этих положений; `unlinked_cards` — привяжи карточку к её положению или удали её из набора (и поправь индексы); `empty_sections` / `sections_without_points` — перечитай часть с этим разделом и выпиши его положения и карточки (раздел без содержания отметь `skipped_reason`). Обнови оба файла и проверь снова — **не больше 3 итераций**. Что осталось непокрытым после трёх — в отчёт, не скрывая;
   - **1** — ошибка формата файлов: исправь по сообщению и проверь снова.

## 4Б. Проверка набора — в обоих режимах, перед отправкой

Правила — разделы «Без воды» и «Смысловые дубликаты» в `card-rules.md`. Отклонённые карточки записывай в `rejected-<время>.json` рядом с файлом карточек: `[{"question": ..., "reason": ..., "duplicate_of": ...}]` (`duplicate_of` — только у дубликатов: вопрос карточки-оригинала).

1. **Вода.** `python3 tools/quiz-import/post_cards.py lint <карточки>`: код 0 — дальше; код 3 — в stdout список `index` / `reason` (`answer_in_question`, `yes_no`, `source_reference`). Каждую такую карточку перепиши так, чтобы она проверяла знание, или удали (в `rejected` с причиной). Оставить без изменений можно только явное ложное срабатывание — одной строкой в отчёте. Затем ещё раз просмотри набор сам по остальным критериям «Без воды» (пересказ примера, расплывчатый ответ) и запусти `lint` снова.
2. **Дубликаты.** `python3 tools/quiz-import/post_cards.py similar <карточки>` — для карточек с кандидатами (`source: "app"` — карточка приложения, `"set"` — более ранняя карточка набора с `index`) реши, **тот же ли это факт**. Не дубликат — оставь. Дубликат — удали из набора и запиши в `rejected` с `duplicate_of`. Код 2 — приложение остановилось: сообщи пользователю.
3. **Автоматический режим:** положение удалённого дубликата карточки приложения получает `"existing": "<вопрос карточки приложения>"` и `"card": null`; дубликат внутри набора — ссылку `card` на оставшуюся карточку. Удалённую «воду» замени новой карточкой на то же положение. Поправь индексы `card` после удаления и снова выполни `coverage.py check` (правила шага 4А).
4. **Явное количество:** если раздел после проверки дал меньше своей квоты, попробуй новые карточки по **другим** фактам этого раздела и проверь их так же. Если новых фактов нет — раздел даёт меньше; набор не добивай повторами и водой.
5. Если после проверки в наборе **не осталось ни одной карточки** — ничего не отправляй и сообщи: новых фактов для карточек нет, всё уже есть в приложении (или в наборе была только вода), перечисли отклонённые.

## 5. Отправить карточки

```bash
python3 tools/quiz-import/post_cards.py post <путь к JSON>
```

Скрипт сам пропускает вопросы, которые уже есть в приложении или повторяются в наборе, отправляет остальные по одной и печатает JSON-отчёт `added` / `skipped` / `failed`. Ошибка одной карточки не останавливает остальные. Код 2 — приложение остановилось между шагами: сообщи об этом пользователю.

## 6. Отчёт пользователю

Кратко, по-русски:

- источник: URL и заголовок страницы;
- **добавлено N**, **пропущено M** (уже были в приложении), **не удалось K**;
- список добавленных вопросов;
- для неудавшихся — вопрос и сообщение `error`;
- **отклонено X** (из `rejected-<время>.json`): каждый дубликат — «<вопрос> → уже есть: <duplicate_of>», каждая вода — вопрос и причина; если после проверки карточек меньше запрошенного — что новых фактов не хватило;
- **покрытие** (кроме запасного пути): строка `обработано <processed_chars> из <total_chars> символов (<P> %)`, числа с пробелом между разрядами, P — доля, округлённая вниз до целого (100 % только при полном тексте);
- **разделы**: каждый раздел, давший карточки, с их числом; отдельной строкой — пропущенные разделы с причиной (`skipped_reason`);
- если карточек меньше запрошенного — по каким разделам не хватило материала;
- если `truncated` — предупреждение: страница длиннее 500 000 символов, обработано начало, не обработано `<100 − P>` % текста;
- для запасного пути — предупреждение из шага 3а;
- **автоматический режим** — вместо пункта «разделы» вывод `python3 tools/quiz-import/coverage.py report <coverage> <карточки>`: строка «ключевых положений: X, покрыто: Y» (и «из них существующими карточками: K», если такие есть) и карточки по каждому разделу; если после трёх итераций сверки что-то осталось непокрытым — список этих положений.

Карточки видны на http://localhost:8080 (или по адресу из `QUIZ_API_URL`).
