# Карточки по PDF-документу

Аргументы: `$ARGUMENTS` — путь к PDF, необязательно диапазон страниц и количество карточек.

Два режима:
- **явное количество N** — до N карточек, распределённых по частям документа (шаг 4);
- **автоматический** (количество не указано) — карточка на каждое ключевое положение выбранных страниц, число карточек определяет содержание, с проверкой полноты (шаг 4А).

Все команды выполняются из корня репозитория. Требования — `openspec/specs/quiz-from-pdf/spec.md`.

## 1. Разобрать аргументы — до проверки приложения и чтения файла

- Первый аргумент — **путь** к локальному PDF (относительно корня репозитория, абсолютный или с `~`). Обязателен. Путь с пробелами пользователь берёт в кавычки.
- Дальше необязательные **диапазон** и **количество**:
  - два аргумента — первый диапазон, второй количество: `file.pdf 3-5 6`;
  - один аргумент вида `N-M` — диапазон: `file.pdf 3-5`;
  - одно число — количество: `file.pdf 15`. Одна страница с количеством по умолчанию — `file.pdf 7-7`.
- Диапазон — `N` или `N-M`, целые, `1 ≤ N ≤ M`. Количество — целое от 1 до 50; если не указано — **автоматический режим**.

**Сообщи пользователю, что именно не так, и остановись**, ничего не читая и не отправляя, если:
- путь не указан или расширение не `.pdf` (без учёта регистра) — например, `.txt`;
- диапазон или количество не соответствуют формату выше.

Существование файла, сам формат PDF и выход диапазона за число страниц проверяет скрипт на шаге 3.

## 2. Проверить, что приложение запущено

```bash
python3 tools/quiz-import/post_cards.py check
```

- Код 0 — продолжай.
- Код 2 — **остановись**: передай пользователю сообщение скрипта (приложение недоступно, запустить `./gradlew bootRun`). Документ не читай, карточки не генерируй.

Адрес API берётся из `QUIZ_API_URL`, по умолчанию `http://localhost:8080`.

## 3. Проверить документ и нарезать его на части

Каталог для результата — `pdf-<время>` в scratchpad-директории сессии (если её нет — во временной директории ОС):

```bash
swift tools/quiz-import/split_pdf.swift "<путь>" [--pages <диапазон>] --count <N или auto> --out <каталог>
```

Скрипт проверяет файл, считает страницы и режет выбранный диапазон на `part-01.pdf`, `part-02.pdf`, … по 10 страниц (больше Read за раз не читает), а в `<каталог>/meta.json` пишет `pages` (всего страниц), `range` и `parts` — `file`, `from`, `to`, `quota` (сколько карточек сделать по части; сумма равна N; при `--count auto` — `null`). Первый запуск компилирует скрипт несколько секунд.

По коду выхода:
- **0** — прочитай `meta.json`, переходи к шагу 4 (явное количество) или 4А (автоматический режим).
- **1** — файл не найден, диапазон выходит за пределы документа или неверные аргументы. **Остановись** и передай сообщение из stderr.
- **3** — файл не открывается как PDF (повреждён или это другой формат). **Остановись**: «не могу прочитать документ» и причина.
- **4** — PDF защищён паролем. **Остановись**: документ прочитать нельзя, ничего не отправлено. Пароль не спрашивай: защищённые документы не поддерживаются.
- **5** — в документе больше 100 страниц, а диапазон не указан. **Остановись**: назови число страниц из сообщения скрипта и попроси вызвать скил ещё раз с диапазоном не больше 100 страниц, например `/quiz-from-pdf <путь> 1-100`. Карточки не генерируй.

## 4. Явное количество: карточки по квотам

1. Прочитай `tools/quiz-import/card-rules.md` и следуй ему полностью.
2. **Дополнительное правило для PDF:** не делай вопросов по служебному тексту — колонтитулам, номерам страниц, оглавлению, списку литературы, титульному листу, подписям к рисункам без содержательного текста.
3. Читай части **по одной, по порядку**: `Read` файла `part-XX.pdf` из каталога шага 3 — **без** параметра `pages` (части не длиннее 10 страниц). Отсканированные страницы Read показывает изображениями: распознай текст с них и работай с ним так же, как с обычным.
4. Для каждой части сделай **ровно** `quota` карточек по содержанию её страниц. Если осмысленного материала в части меньше — сделай меньше (или ни одной) и запомни это для отчёта. Не повторяй вопросы из предыдущих частей. Запоминай, сколько карточек дала каждая часть.
5. Если по всем частям не получилось **ни одной** карточки — на страницах нет текста (пустые страницы, только рисунки) или нет осмысленного содержания. **Остановись**: сообщи, что текста для карточек нет, ничего не отправляй.
6. Запиши все карточки одним JSON-массивом `[{"question": ..., "answer": ...}]` в файл `quiz-import-<время>.json` рядом с каталогом частей. Переходи к шагу 4Б.

## 4А. Автоматический режим: полный охват

Прочитай `tools/quiz-import/card-rules.md` целиком, включая раздел «Полный охват (автоматический режим)», и следуй ему вместе с PDF-правилом о служебном тексте из шага 4. Файлы — рядом с каталогом частей: `coverage-<время>.json` и `quiz-import-<время>.json`.

1. **Положения.** Читай части **по одной, по порядку** (`Read` файла `part-XX.pdf` без параметра `pages`) и выписывай ключевые положения каждой части в `coverage.json` (формат — `card-rules.md`). Раздел — это часть: `id` `p1`, `p2`, …, `title` «стр. <from>–<to>». У всех положений `card: null`. Часть без содержательного текста (титул, оглавление, литература, пустые страницы) — с `skipped_reason` и пустыми `points`. Повтор уже выписанного положения из другой части не добавляй. **Одно положение — одна мысль**: перед записью нового положения проверь, не поясняет ли оно предыдущее положение того же места текста (причина, условие, следствие, противопоставление, способ применения) — если да, дополни текст предыдущего положения, а не заводи новое.
2. Если положений **нет совсем** — на страницах нет текста для карточек. **Остановись**, ничего не отправляй.
3. **Порог 150 — до генерации карточек.** Карточек будет столько же, сколько положений. Если положений больше 150:
   - запиши `[]` в файл карточек и выполни `python3 tools/quiz-import/coverage.py report <coverage> <карточки>`;
   - покажи пользователю число положений и разбивку по частям из отчёта и спроси: **отправить все**, **отменить** или **указать количество** (1–50, тогда скил выполняется заново с этим числом, шаг 4);
   - **заверши ход вопросом** и ничего не генерируй и не отправляй до ответа. «Отменить» — остановись, ничего не отправлено.
4. **Карточки.** По каждому положению сделай одну карточку по `card-rules.md`; ответ должен следовать из текста положения (если без контекста не сформулировать — перечитай часть). Карточки — в один JSON-массив, индекс карточки — в `card` положения. Повторяющиеся положения ссылаются на одну карточку.
5. **Сверка.** `python3 tools/quiz-import/coverage.py check <coverage> <карточки>`:
   - **0** — всё покрыто, переходи к шагу 4Б;
   - **3** — в stdout JSON с пробелами. `uncovered` — сделай карточки для этих положений; `unlinked_cards` — привяжи карточку к её положению или удали её из набора (и поправь индексы); `empty_sections` / `sections_without_points` — перечитай эту часть и выпиши её положения и карточки (часть без содержания отметь `skipped_reason`). Обнови оба файла и проверь снова — **не больше 3 итераций**. Что осталось непокрытым после трёх — в отчёт, не скрывая;
   - **1** — ошибка формата файлов: исправь по сообщению и проверь снова.

## 4Б. Проверка набора — в обоих режимах, перед отправкой

Правила — разделы «Без воды» и «Смысловые дубликаты» в `card-rules.md`. Отклонённые карточки записывай в `rejected-<время>.json` рядом с файлом карточек: `[{"question": ..., "reason": ..., "duplicate_of": ...}]` (`duplicate_of` — только у дубликатов: вопрос карточки-оригинала).

1. **Вода.** `python3 tools/quiz-import/post_cards.py lint <карточки>`: код 0 — дальше; код 3 — в stdout список `index` / `reason` (`answer_in_question`, `yes_no`, `source_reference`). Каждую такую карточку перепиши так, чтобы она проверяла знание, или удали (в `rejected` с причиной). Оставить без изменений можно только явное ложное срабатывание — одной строкой в отчёте. Затем ещё раз просмотри набор сам по остальным критериям «Без воды» (пересказ примера, расплывчатый ответ) и запусти `lint` снова.
2. **Дубликаты.** `python3 tools/quiz-import/post_cards.py similar <карточки>` — для карточек с кандидатами (`source: "app"` — карточка приложения, `"set"` — более ранняя карточка набора с `index`) реши, **тот же ли это факт**. Не дубликат — оставь. Дубликат — удали из набора и запиши в `rejected` с `duplicate_of`. Для кандидатов `source: "set"` есть третий исход — **одна мысль с двух сторон** (утверждение и его следствие, условие, противопоставление; критерий «один вопрос» в `card-rules.md`): **слей** их в одну карточку с одним вопросом и ответом на всю мысль (1–3 предложения), вторую удали, а в `rejected` запиши `{"question": <удалённая>, "reason": "слита с карточкой", "merged_into": <вопрос оставшейся>}`. Код 2 — приложение остановилось: сообщи пользователю.
3. **Автоматический режим:** положение удалённого дубликата карточки приложения получает `"existing": "<вопрос карточки приложения>"` и `"card": null`; дубликат или слитая карточка внутри набора — ссылку `card` на оставшуюся карточку. Удалённую «воду» замени новой карточкой на то же положение. Поправь индексы `card` после удаления и снова выполни `coverage.py check` (правила шага 4А).
4. **Явное количество:** если раздел после проверки дал меньше своей квоты, попробуй новые карточки по **другим** фактам этого раздела и проверь их так же. Если новых фактов нет — раздел даёт меньше; набор не добивай повторами и водой.
5. Если после проверки в наборе **не осталось ни одной карточки** — ничего не отправляй и сообщи: новых фактов для карточек нет, всё уже есть в приложении (или в наборе была только вода), перечисли отклонённые.

## 5. Отправить карточки

```bash
python3 tools/quiz-import/post_cards.py post <путь к JSON>
```

Скрипт сам пропускает вопросы, которые уже есть в приложении или повторяются в наборе (без учёта регистра и пробелов по краям), отправляет остальные по одной и печатает JSON-отчёт `added` / `skipped` / `failed`. Ошибка одной карточки не останавливает остальные. Код 2 — приложение остановилось между шагами: сообщи об этом пользователю.

## 6. Отчёт пользователю

Кратко, по-русски:

- источник: путь к файлу, обработанные страницы `from–to` из `pages`;
- **добавлено N**, **пропущено M** (уже были в приложении), **не удалось K**;
- список добавленных вопросов;
- для неудавшихся — вопрос и сообщение `error`;
- **слито X** (записи `rejected-<время>.json` с `merged_into`): «<вопрос> → в <merged_into>»; слияния не считаются отклонёнными;
- **отклонено X** (остальные записи `rejected-<время>.json`): каждый дубликат — «<вопрос> → уже есть: <duplicate_of>», каждая вода — вопрос и причина; если после проверки карточек меньше запрошенного — что новых фактов не хватило;
- распределение: части (`стр. 1–10`, `стр. 11–20`, …) с числом карточек;
- если карточек меньше запрошенного — по каким страницам не хватило материала;
- **автоматический режим** — вместо пункта «распределение» вывод `python3 tools/quiz-import/coverage.py report <coverage> <карточки>`: строка «ключевых положений: X, покрыто: Y» (и «из них существующими карточками: K», если такие есть) и карточки по каждой части (диапазону страниц); если после трёх итераций сверки что-то осталось непокрытым — список этих положений.

Карточки видны на http://localhost:8080 (или по адресу из `QUIZ_API_URL`).
