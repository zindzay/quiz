# Правила генерации карточек

Общие для скилов импорта (`quiz-from-web-page`, `quiz-from-pdf`). Скил читает этот файл перед генерацией и следует ему полностью.

## Источник

- Карточки строятся **только по предоставленному тексту** источника. Не добавлять факты из собственных знаний, даже если они верны.
- Ответ на каждый вопрос **должен прямо следовать из текста**. Если для ответа нужно домысливать — карточку не создавать.
- Брать только основное содержание: игнорировать навигацию, меню, рекламу, комментарии, подписи «поделиться», cookie-баннеры, списки «читайте также».

## Каждая карточка

- **Один факт или одно понятие** на карточку. Не объединять несколько вопросов в один.
- Вопрос понятен **без источника перед глазами**: не «Что сказано в третьем абзаце?», а «Какой порт по умолчанию использует HTTPS?».
- **Без вопросов да/нет** («Является ли HTTP протоколом?») — переформулировать в открытый вопрос.
- **Без вопросов о самом источнике**: «О чём эта статья?», «Кто автор страницы?», «Когда опубликован текст?».
- **Ответ короткий**: 1–3 предложения или термин, число, определение. Без вступлений вроде «В статье говорится, что…».
- **Язык карточек — язык источника.** Русская страница → вопросы и ответы на русском. Термины, принятые в оригинале на английском (HTTP, TCP), оставлять как есть.
- Длина вопроса и ответа — **не больше 2000 символов** каждый (ограничение API).
- Вопросы в наборе **не повторяют друг друга** по смыслу.

## Набор

- Карточки покрывают **разные части** источника, а не только начало.
- Предпочитать ключевые понятия, определения, причины и следствия, числа и факты, которые стоит запомнить; пропускать второстепенные детали.
- Если осмысленного материала меньше, чем запрошено карточек, — **создать меньше** и сообщить об этом в отчёте, а не заполнять набор слабыми вопросами.

## Формат результата

JSON-массив объектов с двумя строковыми полями, без других полей (в том числе без `id`):

```json
[
  {"question": "Какой порт по умолчанию использует HTTPS?", "answer": "443."},
  {"question": "Чем отличаются коды 401 и 403?", "answer": "401 — клиент не аутентифицирован; 403 — аутентифицирован, но прав на ресурс нет."}
]
```

Файл сохраняется в UTF-8 и передаётся в `python3 tools/quiz-import/post_cards.py post <файл>`.

## Полный охват (автоматический режим)

Применяется, когда пользователь **не указал количество** карточек. Цель — проверить тему источника полностью, поэтому число карточек определяется содержанием, а не задаётся заранее.

### Ключевое положение

Атомарное утверждение источника, которое стоит проверить:
- **определение** — «Домен — множество допустимых значений атрибута»;
- **факт, число или дата** — «Реляционную модель предложил Эдгар Кодд в 1970 году»;
- **причина и следствие** — «Хлорофилл отражает зелёный свет, поэтому листья кажутся зелёными»;
- **шаг процесса** — «В световой фазе происходит фотолиз воды»;
- **сравнение** — «WHERE фильтрует строки до группировки, HAVING — группы после неё»;
- **ограничение или исключение** — «Хеш-индекс не подходит для поиска по диапазону».

Не ключевые положения:
- служебные детали: даты правок, авторы страницы, номера страниц, колонтитулы, оглавление, список литературы, ссылки «см. также»;
- пересказ одного и того же другими словами («как уже говорилось…»);
- примеры, которые ничего не добавляют к утверждению (пример — часть положения, а не отдельное положение);
- оценки без содержания («это очень важная тема»).

Одно положение — одна мысль. Утверждение с перечислением («три уровня: внешний, концептуальный, внутренний») — одно положение; два независимых факта в одном предложении — два положения.

### Правила

1. По каждой части источника сначала **выдели все ключевые положения**, затем сделай по ним карточки. Положения записывай близко к тексту источника, с указанием раздела.
2. **Одно положение — одна карточка.** Карточек столько же, сколько положений; ограничения 50 нет.
3. Положение, повторяющееся в разных частях (во введении и в разделе, в двух главах), — **одно положение и одна карточка**: при повторе сошлись на уже созданную карточку, а не делай новую.
4. Каждый раздел с осмысленным содержанием даёт хотя бы одно положение. Раздел без положений допустим только со `skipped_reason` (справочный, короткий или пустой раздел).
5. Сверку покрытия выполняет `tools/quiz-import/coverage.py`, а не оценка «на глаз».

### Файл покрытия `coverage.json`

Скил ведёт его рядом с файлом карточек. Файл карточек не меняется — в нём по-прежнему только `question` и `answer`.

```json
{
  "sections": [
    {"id": "s3", "title": "Коды состояния", "points": [
      {"id": "s3-p1", "text": "Код состояния — три цифры в первой строке ответа", "card": 7},
      {"id": "s3-p2", "text": "Класс 4xx — ошибки клиента", "card": null}
    ]},
    {"id": "s9", "title": "Примечания", "skipped_reason": "справочный раздел", "points": []}
  ]
}
```

- `sections` — разделы источника по порядку: для веб-страницы — разделы из `meta.json` `fetch_page.py` (`id` вида `s3`), для PDF — части из `meta.json` `split_pdf.swift` (`id` вида `p1`, `title` — «стр. 1–10»).
- `points` — ключевые положения раздела; `id` уникален во всём файле (`s3-p1`, `p1-4`).
- `card` — индекс карточки (с 0) в JSON-массиве карточек или `null`, если карточки ещё нет. Несколько положений-повторов могут ссылаться на одну карточку.
- `skipped_reason` — только у разделов, где положений нет: справочный, короткий или пустой раздел.
