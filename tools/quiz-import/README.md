# quiz-import

Общие инструменты скилов импорта карточек:

```
/quiz-from-web-page <url> [n]
/quiz-from-pdf <путь> [страницы] [n]     # страницы — N или N-M; без диапазона — не больше 100 страниц
/quiz-from-text [-n N] <текст>           # текст из аргументов; количество — только флагом -n
```

Перед отправкой все скилы проверяют набор (`post_cards.py lint` и `similar`): карточки без пользы и смысловые дубликаты карточек приложения или набора отклоняются и перечисляются в отчёте («отклонено: X»).

`quiz-from-text` не использует скрипт нарезки: текст уже в аргументах скила, а разделы — его заголовки `##` (без них — `#`). Из этих инструментов ему нужны `card-rules.md`, `coverage.py` и `post_cards.py`.

Без `n` — автоматический режим: карточка на каждое ключевое положение источника, полнота проверяется `coverage.py`.

```
```

| Файл | Назначение |
|---|---|
| `card-rules.md` | правила генерации карточек — скилы читают его перед генерацией |
| `fetch_page.py` | полный основной текст веб-страницы по частям и квоты карточек по разделам |
| `split_pdf.swift` | проверка PDF, лимит 100 страниц и нарезка на части по 10 страниц с квотами карточек |
| `coverage.py` | сверка покрытия ключевых положений карточками (автоматический режим) |
| `post_cards.py` | проверка API и отправка карточек |
| `test_fetch_page.py`, `fixtures/` | тесты `fetch_page.py` на HTML-фикстурах и локальном сервере |
| `test_split_pdf.py` | тесты `split_pdf.swift` на PDF-фикстурах |
| `test_coverage.py` | тесты `coverage.py` |
| `test_post_cards.py` | тесты `post_cards.py` на поддельном API |

Python-скрипты — только стандартная библиотека; `split_pdf.swift` — PDFKit macOS (`swift` входит в Command Line Tools, как и `python3`).

## fetch_page.py — текст страницы

```bash
python3 tools/quiz-import/fetch_page.py https://ru.wikipedia.org/wiki/HTTP --count 10 --out /tmp/page-http
```

- `URL` — `http://` или `https://`, кириллица в адресе допустима;
- `--count N` — сколько карточек распределить по разделам, 1–50; `--count auto` — автоматический режим: квоты не считаются (`quota: null`), разделы, части и `skipped_reason` — как обычно;
- `--out DIR` — каталог для результата (создаётся).

Скрипт загружает HTML (`User-Agent: quiz-import/1.0`, кодировка из `Content-Type` или `<meta charset>`) и выделяет основной текст в Markdown без пересказа:
- корень — `<main>`, иначе самый объёмный `<article>`, иначе `<body>`;
- выбрасываются скрипты, стили, формы, `nav`, `header`, `footer`, `aside`, элементы с `role` navigation/banner/contentinfo/search, `hidden` и `aria-hidden`, а также элементы, у которых в `class`/`id` есть слово `nav`, `menu`, `footer`, `sidebar`, `cookie`, `comments`, `breadcrumb`, `toc`, `mw-editsection`, `reference` (по словам, а не подстрокам);
- заголовки → `#`, списки → `-` / `1.`, таблицы → строки с ` | `, `<pre>` → блоки кода.

Текст делится на **крупные разделы** (по `<h2>`, без них — по `<h1>`; текст до первого заголовка — «Введение») и упаковывается в **части** до ~12 000 символов; абзацы и блоки кода не разрываются. Справочные разделы («Примечания», «Литература», «Ссылки», «См. также», «References», «See also», «External links», «Notes», «Further reading») и разделы короче 300 символов получают квоту 0. Остальные делят `N`: если `N` не меньше числа разделов — каждому по 1, остаток пропорционально объёму; иначе `N` разделов, равномерно разнесённых по странице, по 1. Сумма квот всегда равна `N`.

Лимит — 500 000 символов основного текста: сверх него обрабатывается начало страницы (`truncated: true`).

Результат в `DIR`:
- `chunk-01.md`, `chunk-02.md`, … — текст частей; их склейка через пустую строку равна обработанному тексту;
- `meta.json`:

```json
{
  "url": "https://ru.wikipedia.org/wiki/HTTP",
  "title": "HTTP — Википедия",
  "count": 10,
  "total_chars": 41437,
  "processed_chars": 41437,
  "truncated": false,
  "sections": [
    {"id": "s1", "title": "Введение", "chars": 1074, "chunks": [1], "quota": 1, "skipped_reason": null},
    {"id": "s10", "title": "Ссылки", "chars": 1153, "chunks": [5], "quota": 0, "skipped_reason": "справочный раздел"}
  ],
  "chunks": [
    {"file": "chunk-01.md", "chars": 11993, "sections": ["s1", "s2", "s3", "s4"]}
  ]
}
```

Коды выхода:
- `0` — готово, в stdout краткая сводка;
- `1` — неверные аргументы;
- `3` — основного текста меньше 500 символов (страница собирается JavaScript) — скил переходит на запасной путь через WebFetch;
- `4` — HTTP-ошибка, недоступный хост или ответ не HTML; сообщение в stderr.

## split_pdf.swift — части PDF

```bash
swift tools/quiz-import/split_pdf.swift tools/quiz-import/fixtures/sections.pdf --count 10 --out /tmp/pdf-sections
swift tools/quiz-import/split_pdf.swift tools/quiz-import/fixtures/sections.pdf --pages 3-5 --count 6 --out /tmp/pdf-3-5
```

Read в Claude Code без параметра `pages` читает PDF до 10 страниц, а `pages` требует poppler, поэтому скил читает документ готовыми частями. Скрипт:
- проверяет, что файл существует и открывается как PDF, и что он не защищён паролем;
- без `--pages` отказывается от документа больше 100 страниц;
- режет выбранный диапазон на `part-01.pdf`, `part-02.pdf`, … по 10 страниц;
- распределяет `--count` карточек по частям (пропорционально числу страниц, сумма равна N; если частей больше N — N равномерно разнесённых частей по 1); `--count auto` — без квот (`quota: null`).

`meta.json`:

```json
{
  "file": "tools/quiz-import/fixtures/sections.pdf",
  "pages": 40,
  "range": {"from": 1, "to": 40},
  "count": 10,
  "parts": [
    {"file": "part-01.pdf", "from": 1, "to": 10, "quota": 3},
    {"file": "part-02.pdf", "from": 11, "to": 20, "quota": 3}
  ]
}
```

Коды выхода: `0` — готово; `1` — неверные аргументы, файл не найден или диапазон вне документа; `3` — не PDF или повреждён; `4` — защищён паролем; `5` — больше 100 страниц без `--pages`. Первый запуск компилирует скрипт несколько секунд.

## coverage.py — сверка покрытия

В автоматическом режиме скил ведёт `coverage.json` (формат — раздел «Полный охват» в `card-rules.md`): разделы источника, их ключевые положения и индекс карточки каждого положения.

```bash
python3 tools/quiz-import/coverage.py check coverage.json cards.json
python3 tools/quiz-import/coverage.py report coverage.json cards.json
```

- `check` — код `0`: всё покрыто; код `3`: в stdout JSON с пробелами — `uncovered` (положения без карточки), `unlinked_cards` (карточки без положения), `empty_sections` (раздел с положениями, но без карточек), `sections_without_points` (раздел без положений и без `skipped_reason`); код `1`: ошибка формата (сообщение в stderr).
- Положение может ссылаться не на карточку набора, а на карточку приложения: `"existing": "<её вопрос>"` вместо `card` (смысловой дубликат, найденный `post_cards.py similar`). Такое положение покрыто без новой карточки; `card` и `existing` вместе — ошибка формата.
- `report` — строка «ключевых положений: X, покрыто: Y» (и «из них существующими карточками: K», если такие есть), число карточек и таблица «раздел | положений | карточек» (со столбцом «уже были» при K > 0); пропущенные разделы — с причиной. С пустым массивом карточек (`[]`) показывает число положений по разделам — так скил проверяет порог 150 до генерации карточек.

## post_cards.py — отправка карточек

### Формат входного JSON

Массив карточек, UTF-8:

```json
[
  {"question": "Какой порт по умолчанию использует HTTPS?", "answer": "443."},
  {"question": "Что такое HTTP?", "answer": "Протокол передачи данных по схеме «запрос — ответ»."}
]
```

### Команды

Приложение должно быть запущено (`./gradlew bootRun`). Адрес API: `--api URL` > `QUIZ_API_URL` > `http://localhost:8080`.

```bash
python3 tools/quiz-import/post_cards.py check          # код 0 — API доступно, 2 — нет
python3 tools/quiz-import/post_cards.py post cards.json
QUIZ_API_URL=http://localhost:9090 python3 tools/quiz-import/post_cards.py post cards.json
```

`post` печатает отчёт:

```json
{
  "added": ["Какой порт по умолчанию использует HTTPS?"],
  "skipped": ["Что такое HTTP?"],
  "failed": [{"question": "…", "error": "Поле «Ответ» длиннее 2000 символов"}]
}
```

- `skipped` — вопрос уже есть в приложении или повторяется в файле (сравнение без учёта регистра и пробелов по краям);
- `failed` — карточка не прошла проверку или API её отклонило; ошибка одной карточки не останавливает отправку остальных.

Коды выхода: `0` — отчёт напечатан, `1` — не удалось прочитать файл, `2` — API недоступно.

### Проверка набора перед отправкой: `lint` и `similar`

```bash
python3 tools/quiz-import/post_cards.py lint cards.json      # код 0 — чисто, 3 — есть находки
python3 tools/quiz-import/post_cards.py similar cards.json   # кандидаты в смысловые дубликаты; код 2 — API недоступно
```

- `lint` — явные признаки карточек без пользы (раздел «Без воды» в `card-rules.md`): `[{"index", "question", "reason"}]`, причины `answer_in_question` (все основы слов ответа есть в вопросе), `yes_no` (ответ «да»/«нет»), `source_reference` (в вопросе «в этом уроке», «в статье», «автор»…). API не нужен.
- `similar` — для каждой карточки до 3 похожих карточек приложения (`source: "app"`) и более ранних карточек набора (`source: "set"`, `index`) со сходством от 0.35: `[{"index", "question", "candidates": [{"source", "question", "answer", "score"}]}]`. Сходство — доля общих основ слов вопроса и ответа от меньшего набора; основы — слова без регистра и служебных слов, кириллица усечена до 5 букв. Порог намеренно низкий: среди кандидатов много карточек на соседние факты той же темы, решение «тот же факт или нет» принимает скил. Перефразирование без общих слов (синонимы) не находится.

## Тестовые PDF

Фикстуры скила `/quiz-from-pdf` в `fixtures/` (вместе ~170 КБ) генерирует `fixtures/make_pdfs.swift` (macOS, AppKit + PDFKit):

| Файл | Страниц | Содержимое |
|---|---|---|
| `short.pdf` | 3 | конспект «Фотосинтез» с колонтитулами и номерами страниц |
| `sections.pdf` | 40 | курс лекций «Базы данных»: титул, оглавление, 6 разделов по 6 страниц, заключение, литература |
| `scanned.pdf` | 2 | «Солнечная система» — страницы-изображения без текстового слоя |
| `blank.pdf` | 3 | пустые страницы и рисунок без текста |
| `protected.pdf` | 1 | защищён паролем `quiz` |

```bash
swift tools/quiz-import/fixtures/make_pdfs.swift fixtures                 # пересоздать фикстуры
swift tools/quiz-import/fixtures/make_pdfs.swift large /tmp/big.pdf 150   # документ больше 100 страниц (не коммитится)
```

В большом документе на каждой странице четыре уникальных синтетических факта, поэтому диапазон `1-60` в автоматическом режиме даёт 240 положений — так проверяется порог 150.

```bash
swift tools/quiz-import/split_pdf.swift /tmp/big.pdf --pages 1-60 --count auto --out /tmp/pdf-big
```
