# quiz

Веб-приложение с карточками «вопрос — ответ» для самопроверки. Карточки можно добавлять вручную в браузере или генерировать автоматически по веб-странице или PDF-документу с помощью скилов Claude Code.

- **Бэкенд:** Java 27, Spring Boot 4, сборка Gradle.
- **Хранилище:** локальный CSV-файл, без базы данных.
- **Интерфейс:** одна страница на Bootstrap 5, светлая и тёмная тема по настройке системы, работает без интернета.
- **Импорт:** скилы Claude Code `/quiz-from-web-page` и `/quiz-from-pdf` составляют карточки по статье или PDF-документу и добавляют их в приложение — заданное количество или столько, сколько нужно, чтобы проверить тему полностью.

## Требования

- **JDK 27** — для сборки и запуска.
- **Python 3** и **Swift** — только для скилов импорта; оба входят в Command Line Tools macOS (`xcode-select --install`).
- **Claude Code** — только для скилов импорта.

Node.js и браузер для UI-тестов ставить не нужно: при первом запуске их скачивает сборка.

## Быстрый старт

```bash
./gradlew bootRun
```

Откройте http://localhost:8080.

Карточки сохраняются в `data/cards.csv`. Если файла нет, он создаётся при первом запуске. Чтобы начать с примера, скопируйте его перед запуском:

```bash
cp data/cards.example.csv data/cards.csv
```

## Работа в браузере

- **Список карточек.** На странице видны вопросы, ответы скрыты. Клик по карточке (или `Enter` / `Пробел` на карточке в фокусе) показывает ответ, повторный клик — скрывает.
- **Добавление.** Заполните поля «Вопрос» и «Ответ» и нажмите «Добавить». Карточка появится в конце списка без перезагрузки страницы. Оба поля обязательны, длина каждого — до 2000 символов. При ошибке введённый текст остаётся в форме.

Редактирования и удаления карточек в интерфейсе пока нет.

## Импорт карточек

Скилы Claude Code составляют карточки по внешнему источнику и отправляют их в **запущенное** приложение:

1. Запустите приложение: `./gradlew bootRun`. Без него скил остановится с подсказкой.
2. Откройте Claude Code в каталоге проекта и вызовите скил — командой или словами: «сделай квиз по статье <ссылка>», «карточки по этому PDF».

Если приложение работает не на `localhost:8080`, задайте адрес перед запуском Claude Code:

```bash
export QUIZ_API_URL=http://localhost:9090
```

### Сколько карточек

- **Указано количество (1–50)** — не больше N карточек, распределённых по всем разделам источника, а не только по его началу. Быстрый режим.
- **Количество не указано — полный охват темы.** Скил выделяет все ключевые положения источника (определения, факты, числа, причины и следствия, шаги, сравнения) и делает по карточке на каждое, без ограничения 50. Затем сверяет, что каждое положение покрыто карточкой, и досоздаёт недостающие. Отчёт показывает «ключевых положений: X, покрыто: X» и число карточек по разделам. Если положений больше 150, скил до генерации карточек показывает их число и спрашивает: отправить все, отменить или указать количество.

Полный охват заметно дороже по токенам: каждое положение выделяется и сверяется отдельно.

Карточки составляются только по содержанию источника и на его языке; служебный текст (меню, колонтитулы, оглавление, литература) в вопросы не попадает. В конце скил выводит отчёт: сколько карточек добавлено, сколько пропущено (такой вопрос уже есть), какие не удалось отправить. Повторный импорт безопасен: вопросы, которые уже есть, пропускаются без учёта регистра и пробелов по краям.

### С веб-страницы

```
/quiz-from-web-page https://ru.wikipedia.org/wiki/HTTP
/quiz-from-web-page https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview 15
```

- Первый аргумент — адрес страницы (`http://` или `https://`), второй — необязательное количество.
- Скил загружает полный основной текст страницы, делит его на разделы и в отчёте показывает, сколько текста обработано: «обработано 41 437 из 41 437 символов (100 %)».
- Справочные разделы («Примечания», «Литература», «Ссылки», «См. также») не используются; текст длиннее 500 000 символов обрабатывается только с начала.
- Страницы, которые собираются JavaScript, скил читает запасным путём через WebFetch — полнота для них не гарантируется.

### Из PDF

```
/quiz-from-pdf ~/Documents/lecture.pdf
/quiz-from-pdf ~/Documents/textbook.pdf 40-60
/quiz-from-pdf ~/Documents/textbook.pdf 40-60 15
```

- Первый аргумент — путь к PDF. Дальше необязательно диапазон страниц (`N` или `N-M`) и количество. Одно число без дефиса — количество; одна страница — `7-7`.
- Отсканированные страницы тоже распознаются.
- В документе больше 100 страниц — укажите диапазон не больше 100 страниц.
- Отчёт показывает карточки по диапазонам страниц (`стр. 1–10`, `стр. 11–20`, …).
- Защищённые паролем PDF не поддерживаются.

Подробнее о скриптах импорта — `tools/quiz-import/README.md`.

## Настройки

Настройки лежат в `src/main/resources/application.properties` и переопределяются переменными окружения:

| Свойство | Переменная | По умолчанию |
|---|---|---|
| `quiz.data-file` | `QUIZ_DATA_FILE` | `data/cards.csv` |
| `server.port` | `SERVER_PORT` | `8080` |

```bash
QUIZ_DATA_FILE=/tmp/cards.csv SERVER_PORT=9090 ./gradlew bootRun
```

## Данные

- Формат CSV: UTF-8, заголовок `id,question,answer`, экранирование по RFC 4180 — значения с запятыми, кавычками и переводами строк сохраняются корректно.
- Приложение держит карточки в памяти и при каждом добавлении атомарно перезаписывает файл. **Редактируйте CSV вручную только при остановленном приложении**, иначе правки будут потеряны.
- Если файл повреждён (неверный заголовок, незакрытые кавычки), приложение не запустится и не изменит файл — в сообщении будет путь к нему.
- `data/cards.csv` не попадает в git.

## HTTP API

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/cards` | `200` — массив карточек в порядке добавления |
| `GET` | `/api/cards/{id}` | `200` — карточка; `404` — нет такой |
| `POST` | `/api/cards` | `201` — созданная карточка; `400` — ошибка проверки |

```bash
curl -X POST localhost:8080/api/cards \
  -H 'Content-Type: application/json' \
  -d '{"question": "Сколько будет 2+2?", "answer": "4"}'
```

Карточка в API выглядит как `{"id": "<uuid>", "question": "...", "answer": "..."}`. Ошибки возвращаются в виде `{"error": "Поле «Вопрос» не может быть пустым"}`.

## Тесты

```bash
./gradlew build                              # всё: JUnit, e2e и скриншотные тесты
./gradlew test                               # только JUnit: репозиторий, сервис, HTTP API
./gradlew e2eTest                            # сценарии интерфейса в браузере (Playwright)
./gradlew screenshotTest                     # сравнение внешнего вида с эталонами
python3 -m unittest discover tools/quiz-import   # скрипты импорта (тесты нарезки PDF требуют swift)
```

- **E2E-тесты** запускают отдельный экземпляр приложения с пустым временным хранилищем на каждый тест, поэтому ваш `data/` не затрагивают.
- **Скриншотные тесты** сравнивают 7 состояний страницы с эталонами в `ui-tests/tests/__screenshots__/`. При расхождении сборка падает и показывает путь к отчёту с разницей. Эталоны сняты на macOS.
- После **намеренного** изменения внешнего вида эталоны обновляются командой `./gradlew screenshotUpdate`. Сначала просмотрите разницу в отчёте: `cd ui-tests && npx playwright show-report`.

## Как ведётся разработка

Проект развивается через [OpenSpec](https://github.com/Fission-AI/OpenSpec): каждая возможность сначала описывается изменением — предложением, спецификацией, дизайном и задачами, — а потом реализуется и архивируется. Команды в Claude Code:

```
/opsx:propose <описание>   спланировать изменение
/opsx:apply <имя>          реализовать
/opsx:archive <имя>        заархивировать и обновить спецификации
```

Правила для разработки и для Claude Code — в `CLAUDE.md`.

## Планы

Активных изменений нет — новые возможности планируются через `/opsx:propose` (см. «Как ведётся разработка»).
